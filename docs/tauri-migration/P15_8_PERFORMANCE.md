# P15.8 1000 章桌面性能基准

## 测量方式

- 被测进程：真实 Tauri 应用（`--features e2e` 专用构建，生产代码路径不变）。
- 数据：通过产品命令（`create_novel` / `create_chapter` / `save_chapter` / `index_knowledge`）写入，固定种子合成中文正文，
  每章约 479 字。没有空章节。
- 指标采样：在 Webview 内用 `performance.now()` 包裹真实 IPC 调用，连续 10 次（导出与备份 3 次），记录 P50/P95。
- 冷启动：独立进程 3 次，测量从 `spawn` 到应用写完“运行时就绪标记”的墙钟时间；标记同时记录数据库迁移与运行时初始化耗时。
- 机器：Apple M1 / 8 GB RAM / macOS 15.7.7；构建模式 `release`（`cargo tauri build --features e2e`）。
- 复现：`SKIP_E2E_BUILD=1 BIZ_NOVEL_PERF_KEEP=1 bash scripts/run-tauri-perf-1000-e2e.sh`。

## 数据规模

| 项目 | 数值 |
| --- | --- |
| 章节 | 1000 |
| 正文字符 | 478,984 |
| 正文 UTF-8 字节 | 1,436,952 |
| 知识文档（已索引） | 200 |
| SQLite 文件 | 24,039,424 字节（22.9 MiB） |

## 结果

| 操作 | 样本 | P50 | P95 |
| --- | --- | --- | --- |
| 章节列表（1000 行，含正文） | 10 | 11 ms | 56 ms |
| 打开章节 | 10 | 1 ms | 2 ms |
| 章节历史 | 10 | 1 ms | 7 ms |
| 运行记录（Task Center） | 10 | 3 ms | 6 ms |
| 连续创作列表 | 10 | 1 ms | 6 ms |
| FTS 检索 | 10 | 11 ms | 61 ms |
| 全书导出（Markdown） | 3 | 14 ms | 15 ms |
| 备份（VACUUM INTO） | 3 | 89 ms | 89 ms |

冷启动（spawn → 运行时就绪）：

| 次 | 墙钟 | 其中数据库迁移+运行时初始化 | RSS |
| --- | --- | --- | --- |
| 1 | 736 ms | 9 ms | 54.8 MB |
| 2 | 1436 ms | 29 ms | 56.8 MB |
| 3 | 353 ms | 8 ms | 58.4 MB |

## 结论与发现

- 1000 章规模下，交互路径都在几十毫秒内：章节列表 P95 56 ms、FTS P95 61 ms，其余 ≤7 ms。
- 备份 22.9 MiB 数据库约 89 ms，恢复切换前的成本可接受。
- 冷启动波动主要来自进程与 Webview 启动（353–1436 ms），数据库迁移与运行时初始化只有 8–29 ms，说明 1000 章数据没有拖慢启动。
- 发现（未在本轮改动）：`list_chapters` 返回全部正文，1000 章约 1.4 MB JSON，P95 56 ms。当前可接受；
  如果章节数继续增长，建议给章节列表加一个不带正文的投影接口，编辑页再单独取正文。

## 未覆盖

- 100 章 / 500 章两档本轮未采样（只有 1000 章）。
- CPU 占用只取瞬时值，没有做持续采样；30 分钟运行内存漂移未测。
- 双窗口场景、Diff 渲染、Structured Memory As-Of 的桌面耗时本轮未采样。
- 未做长事务 / N+1 的定向排查，仅记录了上面的观察。
