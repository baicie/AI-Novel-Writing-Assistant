# P15.8 桌面性能基准（100 / 500 / 1000 章）

## 测量方式

- 被测进程：真实 Tauri 应用（`--features e2e` 专用构建，生产代码路径不变）。
- 数据：通过产品命令（`create_novel` / `create_chapter` / `save_chapter` / `index_knowledge` + 索引任务）写入，固定种子合成中文正文，没有空章节。
- 指标采样：在 Webview 内用 `performance.now()` 包裹真实 IPC 调用，连续 10 次（导出与备份 3 次），取 P50 / P95。
- 冷启动：每个规模独立进程 3 次，测量 `spawn` → 应用写完"运行时就绪标记"的墙钟；标记同时记录数据库迁移 + 运行时初始化耗时。
- CPU / RSS：就绪时与空闲 3 秒后各取一次 `ps -o %cpu=,%rss=`（主进程，不含 Webview 辅助进程）。
- 机器：Apple M1 / 8 GB RAM / macOS 15.7.7；`release` 构建。
- 复现：`bash scripts/run-tauri-perf-1000-e2e.sh`（`BIZ_NOVEL_PERF_SIZES`、`BIZ_NOVEL_PERF_DRIFT_SECS` 可调，`BIZ_NOVEL_PERF_KEEP=1` 保留完整报告）。

## 数据规模

| 章数 | 正文字符 | 正文 UTF-8 字节 | 知识文档 | SQLite |
| --- | --- | --- | --- | --- |
| 100 | 47,925 | 143,775 | 200 | 5.4 MiB |
| 500 | 239,485 | 718,455 | 200 | 13.5 MiB |
| 1000 | 478,984 | 1,436,952 | 200 | 23.3 MiB |

| 操作 | 100 章 | 500 章 | 1000 章 |
| --- | --- | --- | --- |
| 章节列表（含正文） | 8 / 56 | 33 / 242 | 39 / 140 |
| 打开章节 | 3 / 46 | 2 / 13 | 2 / 21 |
| 章节历史 | 2 / 35 | 2 / 4 | 2 / 6 |
| 运行记录 | 6 / 39 | 12 / 22 | 13 / 30 |
| 连续创作列表 | 1 / 3 | 3 / 24 | 2 / 6 |

| 全书导出（Markdown） | 97 / 4470 | 42 / 45 | 48 / 53 |
| 备份（VACUUM INTO） | 501 / 2646 | 253 / 362 | 294 / 354 |

## 冷启动与内存（主进程）

| 章数 | 冷启动 3 次 | 就绪 CPU | 空闲 CPU | 就绪 RSS | 空闲 RSS |
| --- | --- | --- | --- | --- | --- |
| 100 | 760 / 332 / 488 ms | 38.1 / 20.4 / 17.4 % | 0.1 / 0 / 0 % | 54 / 60 / 59 MB | 81 / 74 / 70 MB |
| 500 | 830 / 301 / 309 ms | 24–29 % | 0–1 % | 56–62 MB | 74–92 MB |
| 1000 | 913 / 228 / 346 ms | 24.2 / 20.5 / 11.1 % | 1.3 / 0.1 / 0 % | 56 / 61 / 64 MB | 88 / 91 / 80 MB |

数据库迁移与运行时初始化在冷启动中始终只占 4–14 ms，章数增长没有拖慢打开数据库。

## 结论

- 从 100 到 1000 章，SQLite 从 5.4 MiB 长到 23.3 MiB；P50 全部在 50 ms 内，打开章节 / 历史 / 运行记录 / 连续创作列表的 P95 都在 46 ms 以内。
- 100 章档出现了不成比例的 P95 尖峰（导出 4470 ms、备份 2646 ms、FTS 1343 ms），而 500 / 1000 章档只有
  45 / 362 / 220 ms。这说明尖峰来自每次进程的首次调用（冷缓存、首次读库、首次 FTS 载入），不是规模效应。
  本轮把冷热混在同一个 P95 里，量级结论可用，尖峰结论不可用——下一轮要把预热与稳态分开统计。
- 冷启动墙钟 228–913 ms，几乎全部是进程与 Webview 启动开销；1000 章与 100 章没有可测差异。
- 章节列表在 500 章档 P95 242 ms 偏高（1000 章档反而 140 ms），同样是首次调用的抖动；它返回全部正文
  （1000 章约 1.4 MB JSON），是后续最值得优化的一处。
