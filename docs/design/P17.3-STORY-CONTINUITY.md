# P17.3 故事连续性与创作上下文

## 背景

作者打开第 N 章时，需要知道「截至这一章，哪些事实已经确认、来自哪里、是否还成立」。
现有系统已经有结构化事实、记忆候选、冲突裁决与 Director 上下文组装，但这些能力分散在
不同入口：章节工作台只能看到人物摘要，上下文预览与运行上下文来源不可见。

P17.3 不新建第二套记忆引擎、冲突引擎或上下文组装器，而是：

1. 在既有 As-Of 查询之上增加只读的章节连续性投影；
2. 把既有候选、冲突与事实命令接入章节工作台；
3. 复用 Director 的 `ContextTrace`，提供生成前预览与运行后来源追踪。

## 章节连续性投影

### 输入与语义

- `novelId` + `chapterId`；目标章节顺序与正式版本来自章节目录。
- 只读取 `effective_chapter_order <= 目标章节顺序` 的事实。
- 只把 `truthfulness = confirmed` 且来源章节当前正式版本等于 `source_revision` 的事实
  放进有效事实。
- 来源章节被删除或没有正式版本 → `unavailable`；来源版本已变化 → `stale`。
- `proposed` / `disputed` 只进入冲突展示池，绝不进入有效事实。
- 所有查询都带 `novel_id`；目标章节必须属于本书。

### 输出

`ChapterContinuityProjection`：

- `worlds`：本书绑定的真实世界字段；
- `characters`：人物、角色、当前有效状态、最近变化、待确认候选数；
- `facts`：结构化事实 + 角色状态/时间线/伏笔，带来源章节、版本与证据；
- `staleFacts`：来源失效、需要重新确认的已确认事实；
- `candidates`：截至本章仍待处理的候选，带 `expired` / `canConfirm`；
- `conflicts`：未裁决冲突及其双方来源；
- `limits`：结构化事实、候选、冲突的条数上限与是否截断。

稳定排序：事实按 `(effectiveChapterOrder, 类型优先级, 人物名, factType, id)`；
人物按 `(name, id)`；候选按章节倒序，冲突按章节与创建时间。

### 来源有效性

`list_structured_facts_with_source` 一次读取截至该章的结构化事实并 JOIN 来源章节与
当前正式版本。投影层负责区分 valid / stale / unavailable；仓储不再静默丢弃过期来源。

## 上下文预览

- 复用 `assemble_director_context` 的同一套来源选择、预算估算与 trace 结构。
- 预览模式允许必要来源缺失，但会返回 `blockedReasons`，界面明确阻断生成。
- 输入预算硬上限 `MAX_CONTEXT_TOKEN_BUDGET = 64_000`；低于 512 直接拒绝。
- 只返回 trace，不返回拼好的 Prompt；不调用模型。
- 数据库读取失败按错误返回，不伪装成「没有相关资料」。

## Run 上下文来源

运行执行 context 步骤时，把完整 trace 写入冻结的 `context` artifact。新命令
`get_run_context_trace` 只读取该 Run 自己的 artifact，不读取当前数据库最新状态。
因此运行开始后的新事实不会改写历史 Run 的上下文，也不会修改 RunContract。

## 人工确认与冲突

- 候选确认复用 `confirm_memory_candidate`：章节版本与内容哈希不一致时拒绝；过期候选
  `canConfirm = false`，界面禁用确认。
- 冲突复用 `resolve_memory_conflict`：必须带 `expectedVersion`、`commandId` 与原因；
  结构化冲突的双方来自事实，候选冲突的双方来自候选；界面不会自动覆盖。
- 事实重新确认复用 `confirm_structured_fact`：使用当前来源版本与新的 id，旧事实被标记
  superseded，不再停留在「需要重新确认」。

## 边界与性能

- `list_chapter_headers` 只读取章节标题、顺序与正式版本，不加载全书正文。
- 结构化事实上限 500 条，候选 200 条，冲突 100 条；界面再限制展示 80 条关键事实。
- 目标章节正文只读取当前一章（章节工作台本来就需要）；不扫描全书正文。
- 1000 章 / 40 人物 / 200 条事实的投影在测试中低于 2 秒，实际远低于该上限。

## 禁止事项

- 不把 `proposed` / `disputed` 当 confirmed。
- 不把未来章节事实放进当前 As-Of。
- 不用「最新数据库状态」替换历史 Run 的冻结上下文。
- 不为了接入上下文重写 Prompt Compiler 或新建后台模型调用。
