## 技术决策亮点

### 1. 清晰的分层与依赖管理

- **Domain 层**：零依赖，纯业务规则
- **Application 层**：只依赖 Domain，不依赖 Infrastructure
- **Infrastructure 层**：实现 Application 定义的 Ports
- **Tauri 层**：只负责通信，业务逻辑在 Application

**优势**：易于测试、易于扩展、易于理解

### 2. 类型安全与错误处理

- 使用 Rust 类型系统确保编译期安全
- `thiserror` 库统一错误处理
- SQLx 查询宏编译时验证
- 结构化 DTO 映射，避免运行时错误

**优势**：减少 bug、提高代码质量、易于维护

### 3. 数据库设计

- **SQLite + WAL 模式**：单机性能优，无额外依赖
- **SQLx 嵌入迁移**：版本控制、可重入、编译期验证
- **FTS5 全文检索**：本地开源方案，支持中文分词
- **向量存储预留**：抽象设计，方便后续集成 Qdrant

**优势**：离线优先、性能好、易于备份

### 4. 自研工作流引擎

- **不翻译 LangGraph**：基于领域知识自研，灵活扩展
- **版本化定义**：工作流定义可版本化、可升级
- **持久化日志**：所有步骤可追溯、可调试
- **后台 Worker**：异步执行、自动重试、优雅降级

**优势**：完全掌控、易于定制、运行透明

### 5. 流式响应与实时推送

- **Tauri Channel**：双向通信，支持流式数据
- **LLM Provider SSE**：实时获取生成结果
- **事件缓存**：断点续传、离线继续
- **前端 Transport**：统一适配，HTTP 兼容

**优势**：用户体验好、网络容错强、开发灵活

### 常见问题

**Q：为什么要自研工作流引擎而不翻译 LangGraph？**
A：LangGraph 是高级 DSL，翻译会丧失灵活性。我们的领域需要完全可控的流程、可追踪的日志、离线恢复等，自研引擎更适合。

**Q：SQLite 能否支持高并发？**
A：SQLite WAL 模式可支持多读一写。如未来需要真正的并发写，可迁移到 PostgreSQL，但 Ports 抽象使迁移容易。

**Q：能否直接修改旧 Prisma SQLite 文件？**
A：否。新库是新建的，首版只迁移完整可用数据。这样可以保留旧数据作为备份，降低风险。
