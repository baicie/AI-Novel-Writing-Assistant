# P17 设计：作者体验（Authoring Experience）

定位：把「AI 能生成」推进到「作者愿意每天在这里写」。
本文件只做设计，不含大规模编辑器重构。

## 1. 当前体验问题（以现有实现为准）

| 编号 | 问题 | 证据来源 |
| --- | --- | --- |
| A1 | 写作与 AI 是两套入口：写正文在章节编辑器，让 AI 干活要去 Director / 任务页 | 页面结构（chapters / director 分离） |
| A2 | 一次生成的结果只能整段替换，缺少「选中一段让 AI 改写」的局部操作 | 编辑器无选区级动作 |
| A3 | 质量债、审校结论在另外的页面，作者写作时看不到「这段有什么风险」 | 审校结果与编辑器不同页 |
| A4 | 角色/世界观/记忆需要跳页查看，写作时上下文不可见 | 人物与世界观是独立页 |
| A5 | 批量创作是「配置一个任务然后等」，缺少边写边批量的中间态 | Director 面向整本流水线 |
| A6 | 失败恢复入口分散，作者不知道「该回哪一页继续」 | 任务中心为只读投影，动作在来源页 |

## 2. 信息架构方案

原则：**写作页是唯一主战场，其他模块都是它的抽屉**。

```text
章节工作台（默认落地页）
├─ 左：章节树（卷/章/状态：草稿、已审、有质量债）
├─ 中：编辑器（Markdown 风格纯文本，支持选区）
│   └─ 选区浮条：改写 / 扩写 / 压缩 / 校对 / 问 AI
├─ 右：上下文抽屉（默认折叠）
│   ├─ 本章要点与承接
│   ├─ 出场人物（含记忆摘要）
│   ├─ 相关世界观条目
│   └─ 质量债与审校提示（可点开定位到段落）
└─ 底：生成面板（模型来源 + 环节绑定可见，默认继承书级设置）
```

Director 从「另一个页面」变成「章节工作台的一个模式」：整本规划、批量生成、恢复继续都在同一个右抽屉里展开。

## 3. 设计令牌与界面规范

- 层级用排版与留白表达，不靠边框卡片（延续现有低边框规范）。
- 令牌：
  - 正文区最大行宽 `68ch`，行高 `1.9`，字号三档（正文/紧凑/大字）。
  - 强调色仅用于「AI 建议」与「质量债」，避免与选中态抢视觉。
  - 抽屉宽度两档：`320px`（默认）、`420px`（展开人物记忆）。
- 交互：
  - 选区操作 ≤ 5 项，优先级：改写 > 扩写 > 压缩 > 校对 > 问 AI。
  - AI 结果一律「先预览后落笔」，落笔支持「整段替换 / 追加 / 仅取某句」。
  - 所有失败恢复动作留在来源页（与现有「任务中心只读」规则一致）。

## 4. 章节编辑器与 Director 整合

| 能力 | 入口 | 说明 |
| --- | --- | --- |
| 单章继续写 | 编辑器工具栏 | 用书级绑定，按环节路由（draft → writer） |
| 选区改写 | 选区浮条 | 只发送选中文本 + 本章要点，不发送全书 |
| 本章审校 | 右侧抽屉 | 结果按段落定位，可一键生成修复建议 |
| 批量 N 章 | 抽屉「批量」页签 | 复用现有 Director 任务，但进度回流到章节树 |
| 恢复继续 | 章节树 + 抽屉提示 | 展示「上次停在哪、下一步做什么」 |

## 5. 版本范围与任务划分

- **P17.0（体验骨架）**：章节工作台三栏布局、选区浮条、结果预览与落笔。
- **P17.1（上下文可见）**：人物记忆、世界观、质量债进右抽屉。
- **P17.2（批量内联）**：Director 批量能力以页签形式内联，进度写回章节树。
- **P17.3（可访问性与规模化）**：大章节性能、键盘流、暗色主题一致性。

## 6. 验收标准

1. 新建书 → 在章节工作台完成「写→AI 改写→审校→修复」全流程，不离开页面。
2. 选区改写只发送选区 + 必要上下文（可用 mock 断言请求体不含全书正文）。
3. 每条质量债都能从抽屉点回对应段落。
4. 批量任务失败后，作者在章节树能直接看到恢复入口。
5. 任何 AI 结果都必须先预览后落笔，不存在「静默覆盖已有正文」。

## 7. 可交给执行代理的提示词

```text
目标：实现 P17.0 的章节工作台骨架。
范围：client 端章节页与编辑器组件；不改后端运行时契约。
要求：
1. 三栏布局（章节树 / 编辑器 / 可折叠右抽屉），沿用项目自有 UI primitives 与语义色变量。
2. 编辑器支持选区，选区浮条提供 5 个动作，默认「改写」。
3. AI 结果先进入预览态，用户确认后才写入正文；不提供静默覆盖。
4. 生成请求沿用现有模型绑定（书级默认 + 环节路由），不在前端拼地址。
5. 所有新增文案从作者视角描述能做什么、下一步是什么，不写实现说明。
验收：typecheck 通过；新增组件有渲染测试；交互留待用户人工验收。
```
