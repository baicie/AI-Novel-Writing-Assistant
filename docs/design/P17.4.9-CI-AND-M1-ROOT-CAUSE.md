## 5. PR #20 正确性审查

### 5.1 归一化

- `mystery_box` 数组按“；”连接，保留全部非空文本；camelCase 映射到 snake_case；文本
  数组连接；`setpiece_seeds` 字符串包装为单元素数组。
- `conflict_layers` 字符串包装为 `{ "external": 文本 }`，保留了文本，但把整段内容归入
  external 层，属于语义归类假设（P2）。
- 数字/布尔转字符串可能让占位值通过校验（P2）；空数组/非法对象仍失败，不编造内容。

### 5.2 一次有界修复

- 只发起一次修复调用；Prompt 包含原任务、步骤硬性要求、错误与原始输出；修复后重新完整
  校验；失败进入 `DataIntegrity` 或 `ProviderUnavailable`，没有循环。
- 修复调用与首次调用共享取消令牌；取消进入 `cancelled`。
- 结构化步骤不提交章节；不会产生重复章节或重复冻结正文。
- 修复成功时 usage 合并；本轮补齐失败/取消路径的 usage 记录。

### 5.3 取消语义

本轮修复前的真实缺陷：

- Director 页面的取消只调用 `cancel_run`，没有中止在途模型请求；取消后 Worker 仍可能
  发起修复调用，造成取消后的额外请求/费用。
- 结构化校验失败后如果修复调用失败或被取消，首次调用已获得的 usage 没有被记录。

修复后：`cancel_run` 成功即取消生成令牌；失败路径先记录 usage 再进入暂停/取消。新增
回归用例覆盖取消前、首次调用中、修复中、Provider 不可用、失败用量与取消后重开。

### 5.4 仍未解决的 P2

1. `consistency_review` 的 JSON 修复可能把异常审校变成空 issues，缺少 fail-closed 标记。
2. `conflict_layers` 字符串统一归入 external。
3. 数字/布尔文本字段字符串化。
4. `chapter_list` 规划上下文未包含 `story_macro`。
5. `chapter_plan_for_target` 匹配失败时静默为空，没有按必要来源失败。
6. 修复成功后、持久化前的取消窄窗口没有专用测试；控制 CAS 会拒绝迟到写入，但尚未覆盖
   结构化步骤的该窗口。
7. `LlmError::Unavailable { billed: true }` 的“可能已计费”调用仍不会形成 usage 行。
