# P17.4.7 D 场景修复：桌面端手动世界与角色创建

## 结论

D1/D2 的桌面本地内核缺口已修复：

- 本书世界可以直接创建并绑定，不再依赖服务端 `novel-world` 副本接口；
- 角色可以在桌面端直接创建，不需要模型，也不再要求基础角色库可用；
- 创建时可填写当前目标与与主角关系，写入本地角色档案；
- 世界创建后角色/世界面板能刷新出结果；
- 角色创建成功后弹窗立即结束“创建中”，不再被可选面板的后台刷新锁住。

状态：`READY_FOR_REVIEW`（Draft PR，未合并）。

## 1. 根因

桌面适配器缺少以下路由，UI 却照常展示入口：

```text
GET  /novels/:id/novel-world
POST /novels/:id/novel-world/manual
POST /novels/:id/novel-world/import
GET  /novels/:id/world-slice
GET  /novels/:id/characters
POST /novels/:id/characters
```

本地内核已有 `create_world`、`list_worlds`、`update_novel(worldId)`、`create_character`，
缺的是把“本书世界”和“角色创建”映射到这些本地命令的适配层。角色弹窗的 AI 路径依赖模型，
基础角色库又是服务端能力，导致没有模型时无法新增角色。

## 2. 修复

### 2.1 本书世界

`client/src/platform/desktopApiAdapter.ts` 新增：

- `GET /novels/:id/novel-world`：读取 `novel.worldId`，与 `list_worlds` 组合成
  `NovelWorldView`；没有绑定时返回空视图。
- `POST /novels/:id/novel-world/manual`：`create_world` 创建世界，`update_novel` 绑定本书，
  返回新视图。
- `POST /novels/:id/novel-world/import`：从世界库选择一份世界并绑定本书。
- `GET /novels/:id/novel-world/sync-diff`：返回“本书世界独立保存、暂不与外部库同步”的明确结果。
- `POST /novels/:id/novel-world/generate`：给出明确提示，引导使用自定义空白手册或样本库导入。
- `GET /novels/:id/world-slice`：返回空切片视图，避免世界页因可选切片接口报“未接入”。

`client/src/platform/desktopTransport.ts` 新增 `createWorld` 包装。

数据仍然只写入本地 SQLite，不调用服务端，不改变服务端的 `novel-world` 语义。

### 2.2 角色

`desktopApiAdapter` 新增：

- `GET /novels/:id/characters`：映射到本地 `list_characters`；
- `POST /novels/:id/characters`：生成角色 ID，调用本地 `create_character`，返回 UI 需要的
  `Character` 形状。

`CharacterCreateDialog` 在桌面端：

- 隐藏“AI 生成角色卡”和基础角色库导入，显示“直接创建空白角色”；
- 角色名称、定位、当前目标、与主角关系随创建一起保存；
- 明确提示“不需要模型”。

`create_character` 命令新增可选 `profile`，本地 `character.profile_json` 保存
`outerGoal`、`currentGoal`、`relationToProtagonist` 等字段；列表与加载映射回 UI。

`useNovelCharacterMutations` 的快速创建在成功后先结束 mutation，角色详情/时间线在后台刷新，
避免可选面板的慢查询把弹窗锁在“创建中”。

## 4. 残余问题（P2）

- 工作台侧栏仍会请求 `volumes`、`quality-report`、`character-resources`、导演投影等
  未迁移面板，页面上仍可能出现“暂未接入桌面本地内核”的提示。这不影响 D1/D2 的创建结果，
  但需要在公开 Beta 前收敛为禁用/空态或迁移。
- 基础角色库仍是服务端能力；桌面端通过“直接创建角色”提供替代路径。
- 角色档案的后续编辑（PUT `/novels/:id/characters/:characterId`）仍未迁移；本轮保证
  创建时写入目标/关系并展示，编辑能力作为下一项 P2。
- 世界“根据本书生成”仍依赖 AI/服务端生成；桌面端保留明确引导，不静默失败。
