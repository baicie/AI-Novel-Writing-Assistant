# P17.4 伏笔生命周期、时间线与剧情因果

## 背景

P17.3 已经让章节工作台理解「截至本章已确认的事实」，但伏笔仍只是一个 `plot_thread`
状态字段，缺少从埋设、推进、回收、暂停/废弃到失效的完整生命周期，也缺少可审计的时间线
与因果关系。P17.4 在既有 `plot_thread`、`timeline_event`、`character_state` 与
Context Assembly 之上做最小增量，不新建第二套故事事实仓储。

## 数据模型

### `plot_thread`

- `status` 是唯一生命周期字段：`open`（埋设）、`developing`（推进）、`resolved`（回收）、
  `deferred`（暂停）、`abandoned`（废弃）、`stale`（来源失效）、`superseded`（历史兼容）。
- 新增 `version`：状态转换 CAS。
- 新增 `last_development_chapter_order`：最近一次推进章节。
- `source_chapter_id` / `source_revision` / `evidence_json` 记录最近一次有效来源。

### `plot_thread_event`

每次埋设/推进/回收/暂停/废弃/恢复都追加一行，包含章节、版本、证据、前后状态、
`command_id` 与 `request_hash`。事件是审计与 As-Of 推导的基础，不覆盖历史。

### `plot_causality_edge`

从真实事件、伏笔或已确认结构化事实指向另一个真实实体；记录关系、证据、来源章节/版本、
状态与版本。同一本书内相同四元组 + 关系唯一。

## As-Of 规则

- 伏笔的 As-Of 状态来自「目标章节之前最近一条来源有效的事件」：
  - 第 5 章只有 setup/develop 事件 → 显示 open/developing；
  - 第 10 章的 payoff 事件只在第 10 章及之后可见。
- 事件来源章节的当前正式版本必须等于事件记录的版本，且证据仍存在于正文；
  否则该事件不参与 As-Of，伏笔显示 stale/待处理。
- 章节被改写时，`invalidate_story_facts()` 在同一事务内把 `plot_thread` 标为 `stale`；
  旧的 `character_state` / `timeline_event` 同步失效。
- 合法延迟：来源章节顺序可以小于生效章节（先埋下、后生效）；反过来的事实不能成立。

## 生命周期与幂等

- `develop`：open/developing/deferred/stale → developing；章节不能早于埋设章。
- `payoff`：open/developing/deferred/stale → resolved；必须有当前章节真实证据，记录回收章。
- `defer`：open/developing → deferred。
- `abandon`：open/developing/deferred/stale → abandoned。
- `recover`：stale → developing；必须提供新证据。
- 所有转换带 `expectedVersion`；同一 `commandId` + 相同请求哈希幂等返回，不同请求冲突。
- 模型建议不能直接调用状态转换；只有作者操作可以。

## 因果关系

- 端点只允许 `timeline_event` / `plot_thread` / `structured_fact`，且必须属于同一本书。
- 拒绝自引用；用现有已确认边做 DFS 检测循环；缺少真实端点或证据时拒绝。
- 来源章节变更后，边保留但 `sourceValid=false`，界面显示待处理，不冒充可靠。
- 本轮只做列表与详情，不做复杂关系图。

## 上下文与预算

- Context Assembly 继续通过 `story_facts` 读取事件与伏笔；只读取 As-Of 有效来源。
- 每条来源保留 `sourceType/sourceId/sourceStatus` 与内容指纹；历史 Run 的冻结 trace 不变。
- 不新增后台模型调用；死链/失效来源不会触发自动修复。

## 边界

- 时间线读取有上限（500 条），超出提示截断。
- 不加载全书正文；来源证据按章节/事件读取。
- 不删除历史事实或事件；失效通过状态与 As-Of 表达。
- 世界规则仍未独立建模，不在本轮伪造。

## P17.4.1 修正（终审）

- 读取投影区分 `lifecycleStatus`（事件折叠出的生命周期）、`storedStatus`（数据库原值）、
  `sourceValid`（来源版本与证据）与 `status`（作者看到的综合状态）。来源失效时 `status=stale`，
  但 `lifecycleStatus` 仍保留 `resolved`/`developing` 等历史语义。
- 动作白名单按综合状态判断：存储仍是 `resolved`/`deferred` 但来源失效时，仍允许
  `recover`/`payoff`/`abandon`；非回收动作会清空旧的回收章节。
- 新动作章节顺序不得早于已有最新事件；更早章节只读，界面提示到最新动作章节继续。
- 事件折叠按当前章节目录顺序计算；同章同毫秒按真实写入顺序（rowid）折叠。
- 旧 `plot_thread` 行没有事件时，`resolved` 只在回收章不晚于 As-Of 时显示。
- 记忆候选重新确认只允许 `disputed → open`，不得重开已结束伏笔，也不得覆盖事件行的来源。
- 时间线超过 500 条时保留最近条目；伏笔事件来源失效保留历史但显示“来源失效”。
- 因果边增加 `fromValid`/`toValid`；端点被替代、事实失效或章节删除时显示“引用对象失效”。
