# P17.4.7 真实模型质量评测手工流程

> 状态：`NOT_RUN`。本轮没有自动调用任何付费模型，也没有写入 API Key。
> 只有在你明确授权模型、费用预算和模型配置后，才按下文执行；执行前不得填写评分。

## 1. 授权与安全边界

执行前先书面确认：

- 使用的供应商与模型（provider / model）；
- 费用预算（单次上限与总预算）；
- 允许使用的测试小说与章节范围；
- 是否允许把生成文本保存到仓库的验收目录。

执行规则：

- API Key 只通过应用设置或本机环境配置，**不写入仓库、日志、报告、截图或评测表**。
- 使用独立验收数据目录，不接触正式作品；测试小说先备份。
- 每次模型调用都在评测表里记录时间、场景、模型与估算费用；不要批量重试未知失败。
- 未经授权时，所有评分为 `NOT_RUN`，不能用 Mock 结果或主观推测代替。

## 2. 测试小说

优先使用满足以下条件的作品：

- 20–30 章以上，已有稳定的人物卡、世界观与至少 3 条伏笔；
- 已确认若干历史事实与时间线事件；
- 允许用于评测，且已备份。

记录：书名、作品 ID、章节范围、人物数量、伏笔数量、事实数量、备份路径。

## 3. 评测场景（10 个）

沿用 P17.4.6 的场景体系（首章、续写、多角色对话、长距离连续性、伏笔、事实冲突、
修改后重新生成、长篇 Director），并补充时间线因果与高压修改两个场景。

| 编号 | 场景 | 操作 | 重点观察 |
| --- | --- | --- | --- |
| M1 | 新小说第一章 | 从一句灵感或简介生成第 1 章 | 入戏速度、人物目标、可继续性 |
| M2 | 基于上一章续写 | 选择第 N 章正文作为上一章，生成第 N+1 章 | 承接、悬念兑现、节奏 |
| M3 | 多角色对话 | 让 3 个以上角色在同一场景对话 | 声音差异、关系张力、信息释放 |
| M4 | 长距离人物连续性 | 从第 5 章推进到第 25 章后检查人物状态 | 目标、关系、能力、伤损是否一致 |
| M5 | 伏笔暗示 / 推进 / 回收 | 分别生成埋设、推进、回收章节 | 伏笔是否可追溯、回收是否有证据 |
| M6 | 已确认事实冲突防护 | 在新的章节里引入与已确认事实冲突的设定 | 是否避免冲突或明确处理 |
| M7 | 修改正文后的重新生成 | 改写来源章节后，重新生成受影响的伏笔/事实 | 旧证据是否失效、是否要求重新确认 |
| M8 | 长篇多轮 Director 创作 | 连续推进 5–10 章 | 上下文选择、阶段目标、重复与漂移 |
| M9 | 时间线因果一致性 | 生成包含 A→B→C 因果链的章节 | 因果顺序、来源可追溯 |
| M10 | 高压修改 | 连续 3 轮局部修文 | 是否越改越差、是否保留作者意图 |

每次执行前记录当前章节的 As-Of 状态（人物、伏笔、事实、时间线），避免用未来信息判断。

## 4. 评分维度（1–5 分）

| 维度 | 1 分 | 3 分 | 5 分 |
| --- | --- | --- | --- |
| 文学表达 | 语句不通或模板化 | 可读，偶有亮点 | 有稳定文风与画面感 |
| 情节连贯 | 前后矛盾 | 基本承接 | 因果紧密、钩子有效 |
| 人物一致性 | 明显 OOC | 大体一致 | 目标、关系、语言稳定 |
| 世界观一致性 | 规则冲突 | 少量偏差 | 规则自洽且被使用 |
| 伏笔质量 | 埋设/回收断裂 | 可追踪 | 有铺垫、有回收、有意外 |
| 创作可控性 | 不服从指令 | 基本服从 | 能按范围与风格调整 |
| 上下文利用 | 忽略设定 | 使用部分资料 | 精准使用相关事实 |
| 修改成本 | 几乎重写 | 需要中等修改 | 少量润色即可 |

同时记录客观指标：

- 生成耗时、输入/输出 token、模型配置、估算费用；
- 失败原因（超时、限流、空输出、JSON 不可用等）；
- 人工修改次数、修改前后字数、修改比例、耗时；
- 是否出现未来剧情泄漏（是/否，指出章节）；
- 是否出现已确认事实冲突（是/否，指出事实编号与证据）。

修改比例 = `(新增字数 + 删除字数) / 生成字数`。超过 60% 视为高修改成本。

## 5. 人物与剧情错误的判断方法

1. 打开人物卡，核对目标、关系、能力、伤损与当前章节是否一致。
2. 打开当前章节的剧情线索 As-Of，核对伏笔状态与最近一次动作。
3. 打开时间线与已确认事实，核对事件顺序、来源章节与证据。
4. 对每个错误记录：
   - 错误类型（人物 / 世界观 / 时间线 / 事实 / 伏笔 / 因果）；
   - 生成文本中的原句；
   - 对应的人物卡、事实或章节证据；
   - 是否属于未来剧情泄漏。
5. 不能只写“感觉不对”，必须能指到具体章节或资料。

## 6. 证据保存

每次评测建立一个目录：

```text
docs/reviews/assets/p17-4-7/model-eval/<M1..M10>/
  output.md        # 生成文本（如允许入库）
  meta.json        # 模型、参数、耗时、token、费用、章节、时间；不含 Key
  screenshot.png   # 生成界面与上下文（可选）
```

如果不允许把生成文本入库，把 `output.md` 放在验收机本地，只在报告里记录路径与摘要。
