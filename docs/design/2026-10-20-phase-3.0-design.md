### 2.1 Task 1 —— 核心领域实体定义（Domain Layer）

**目标**：定义不依赖数据库的纯业务规则

**具体工作**：

1. 定义 `Novel` 实体
   - 基本属性：ID、标题、作者、简介、分类、标签
   - 状态机：`Created → Planning → InProgress → Completed → Archived`
   - 不变量：标题非空、同一用户不重名

2. 定义 `Chapter` 实体
   - 基本属性：ID、小说 ID、章节号、标题、内容、字数
   - 生成与评审状态：`Draft → Pending → Approved → Published`
   - 版本管理：`generationState`、`chapterStatus`、快照保存

3. 定义 `World` 与 `Character` 实体
   - World：设定名、类型、描述、关键属性
   - Character：人物名、角色定位、性格、关系、发展弧线
   - 关系：多个 Character 与 World 属于同一 Novel

4. 定义 `RunContract` 与 `WorkflowStep`
   - Run：任务唯一标识、状态、进度、质量债记录
   - Step：步骤类型、输入/输出、执行状态、重试机制

5. 类型安全与 Serde 集成
   - 所有实体实现 `Serialize` / `Deserialize`
   - 定义统一错误类型 `DomainError`
   - 验证规则用 validator crate 或自实现

**验证**：
- 单元测试覆盖实体创建、状态转移、不变量检查
- Rust 编译通过，无 warning

**文件位置**：`crates/novel-domain/src/entities/`

### 2.2 Task 2 —— 数据库持久化层（Storage Layer）

**目标**：建立 SQLite 数据库及迁移基础

**具体工作**：

1. 项目结构初始化
   - 新建 crate：`novel-storage-sqlite`
   - 依赖：`sqlx`、`tokio`、`serde_json`、`uuid`
   - Feature flags：`runtime-tokio`、`sqlite`、`migrate`

2. 数据库迁移框架
   - 配置 SQLx CLI 与迁移脚本目录
   - 实现嵌入迁移（使用 `sqlx::migrate!` 宏）
   - 迁移 001：初始化 Novels、Chapters、Worlds、Characters 表
   - 迁移 002：添加索引与外键约束

3. 表结构设计
   ```sql
   CREATE TABLE novels (
     id TEXT PRIMARY KEY,
     title TEXT NOT NULL,
     author TEXT,
     description TEXT,
     status TEXT NOT NULL DEFAULT 'Created',
     created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
     updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
     ...
   );
   
   CREATE TABLE chapters (
     id TEXT PRIMARY KEY,
     novel_id TEXT NOT NULL REFERENCES novels(id),
     chapter_number INTEGER NOT NULL,
     title TEXT NOT NULL,
     content TEXT,
     word_count INTEGER,
     generation_state TEXT,
     chapter_status TEXT,
     created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
     updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
     UNIQUE(novel_id, chapter_number)
   );
   
   -- 类似地：worlds、characters、runs、steps 等表
   ```

4. Repository 接口定义（Ports）
   - 定义 trait：`NovelRepository`、`ChapterRepository` 等
   - 在 `application` 层定义，`storage-sqlite` 层实现
   - 支持异步操作（`async/await`）

5. SQLite 适配实现
   - 实现 `NovelRepositorySqlite` for `NovelRepository`
   - 操作：Create、Read、Update、Delete、List、Query
   - 使用 SQLx 查询宏和参数绑定（无 SQL 注入）

6. 连接池与生命周期
   - 使用 `SqlitePool` with WAL mode
   - 初始化逻辑：创建/打开数据库文件、运行迁移、配置 pragma

**验证**：
- 编译通过，SQLx CLI 验证迁移脚本
- 集成测试：创建内存 SQLite 数据库，验证 CRUD 操作
- 验证迁移可重入（多次运行不报错）

## 3. 技术决策与风险管理

### 3.1 关键决策

| 决策 | 理由 | 风险 |
| --- | --- | --- |
| SQLite + SQLx | 离线优先，无依赖，查询宏类型安全 | 并发限制，需连接池 |
| Rust Workspace 多 crate | 清晰的模块边界与依赖管理 | 初期设置复杂，编译时间长 |
| 自研 Workflow Engine | 不强依赖 LangGraph，灵活扩展 | 需要充分测试与文档 |
| FTS5 全文检索 | 本地开源方案，无额外依赖 | 中文分词需单独处理 |

### 3.2 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 编译时间长 | 开发迭代慢 | 使用 cargo-incremental，分阶段构建 |
| SQLite 并发瓶颈 | 性能下降 | WAL mode，连接池，后续可迁移 |
| Tauri 兼容性 | 桌面支持不足 | 定期测试各平台，建立兼容性矩阵 |
| LLM API 变更 | Provider 失效 | 抽象设计，支持多家模型 |
