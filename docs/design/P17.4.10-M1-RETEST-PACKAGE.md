# P17.4.10 M1 复测包（未执行）

## 目的

本包只定义 M1 的固定输入、产物保留与判定标准。**未获得新凭据、明确授权与费用上限前，
不得调用真实模型。** M1 当前为 `FAIL / RETEST_PENDING`，M2–M10 为 `NOT_RUN`。

## 1. 固定输入

### 1.1 用户创作要求

沿用 P17.4.7 M1 样本，避免换题导致不可比：

```text
书名：P17.4.7 模型评测样本
简介：边陲小镇的少年在雪夜发现一枚会发光的旧玉佩，由此被卷入山门与一桩旧案。
预计章节数：30
```

### 1.2 第 1 章目标

```text
第1章：林动在雪夜发现玉佩，随后亲眼撞见老铁匠被灭口。
```

### 1.3 第 1 章义务（复测前由 Planner 输出，允许等价措辞但必须包含同等约束）

| ID | 类型 | 强制 | 内容 |
| --- | --- | --- | --- |
| `ch1-req-1` | required_event | hard | 林动亲眼撞见老铁匠被杀 |
| `ch1-req-2` | required_event | hard | 林动在事件发生时在场 |
| `ch1-causal-1` | causal_constraint | hard | 目击灭口是林动被卷入旧案的直接原因 |
| `ch1-order-1` | ordering_constraint | hard | 先发现雪夜异响，再撞见灭口 |
| `ch1-forbid-1` | forbidden_event | hard | 不得写成“到达时老铁匠已经死亡”或等价的事后到场 |

`advisory` 只允许用于普通氛围、文风与场景细节，不得把关键事件降级为建议。

## 3. 产物保留

每个 Run 必须保留脱敏后的：

1. `story_macro`、`character_cast`、`volume_strategy`、`chapter_list` 产物 JSON。
2. `context` 产物：`promptText`、`chapterPlanVersion`、`obligationIds`、
   `obligationsText`、`trace.sources`。
3. `chapter_draft` / 候选正文。
4. `consistency_review` 的 issueDetails（含 obligationId/evidence/severity）。
5. `chapter_repair` 的输入问题清单与输出正文。
6. Run 状态、usage、pauseSignal、最终候选/章节的 SHA256。
7. 所有 Prompt 的脱敏副本（只保留结构化字段与必要正文，不保留凭据）。

禁止保留：API Key、完整系统凭据、用户真实作品、未脱敏的个人信息。

## 4. 事件一致性判定

### 4.1 确定性检查（必须）

- Planner 的 `chapter_list` 含目标章节 obligations，且 ID 唯一。
- Context 的 `obligationIds` 与目标章节计划一致；无未来章节 ID。
- Reviewer 的每个 hard 义务违反项有 `obligationId`，且 ID 存在。
- 无效审校 JSON/未知 ID → 暂停，不作为零问题通过。
- 修复后复验保留原义务 ID；正文变更不涉及义务本身。

### 4.2 语义检查（人工/授权评审）

- 林动是否在灭口发生时在场，而不是事后到达。
- 老铁匠是否在事件中被杀，而不是此前已死。
- 目击是否成为林动卷入旧案的因果起点。
- 关键事件顺序是否与计划一致。
- Reviewer 的 evidence 是否逐字来自当前候选正文，而不是历史正文。

### 4.3 M1 通过标准

- 无 high 级事件/因果/时间线矛盾。
- hard 义务全部满足，或至少有一次有界修复后收敛。
- Reviewer 的 violation 引用正确 obligationId 与证据。
- 人工/授权评审确认正文可读、事件可理解，并记录修改成本。
- 任一 high 矛盾、义务未满足或审校不可审计 → M1 FAIL。

## 5. 人工修改成本记录

每章至少记录：

| 项 | 说明 |
| --- | --- |
| 修改耗时 | 从候选到作者可接受正文的分钟数 |
| 修改范围 | 句子/段落/场景/整章 |
| 是否改动关键事件 | 是/否；是则记录原因 |
| 是否改动义务 | 不允许；若需要改计划，必须走作者确认/版本流程 |
| 作者主观评分 | 1–5（可读性、连贯性、人物一致性） |
