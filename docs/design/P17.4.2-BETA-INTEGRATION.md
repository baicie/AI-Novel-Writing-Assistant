## 4. 集成前正确性补充（G1—G4）

### G1：旧伏笔与 Director 上下文

问题：`list_story_facts` 对没有事件历史的 `plot_thread` 无条件视为来源有效。无证据旧行会进入
Director 可信上下文；`stale`/`superseded`/`disputed` 已由状态过滤，但无证据旧行没有过滤。

- `crates/novel-storage-sqlite/src/novels.rs` 的 `plot_as_of` 对无事件行重新计算来源有效性：
  - 必须有 `source_chapter_id`、非空证据（伏笔自身证据或关联记忆候选证据）；
  - `source_revision` 解析后必须等于来源章节当前正式版本；
  - 证据必须仍存在于当前正式正文。
- 不删除旧数据。旧行仍可在「剧情线索」中查看、显示 stale、用新证据恢复；只是不进入
  `list_story_facts` 与 Director 上下文。
- 有来源且证据可核对的旧行继续进入上下文。
- 旧行无事件时 `resolved` 仍只在 `resolved_chapter_order <= As-Of` 时显示，沿用 P17.4.1 规则。

回归：

- 新增 `trusted_context_excludes_unverifiable_and_stale_plots`：真实 SQLite + `assemble_director_context`，
  断言有效旧伏笔进入 prompt，无证据旧伏笔与来源失效伏笔不进入。
- 更新 `p13_story_memory`：无来源旧伏笔不再出现在 `list_story_facts` 与上下文，数据仍保留。
- 既有的 `legacy_resolved_thread_does_not_leak_into_earlier_chapters`、
  `invalid_legacy_thread_can_recover_with_new_evidence` 继续覆盖 As-Of 与恢复。
