# P17.1 作者创作闭环设计

> 状态：设计已定稿，实现仅完成 P17.0.1 的缺陷收口（见 `P17.0.1-CODE-REVIEW-CLOSURE.md`）。本文件描述目标形态与依赖。

## 1. 目标

把「章节工作台」从导航 + 运行面板，推进到**真实创作闭环**：作者选中正文 → AI 改写 → Diff 预览 → 部分应用 → 保存 → 切章返回一致 → 重启仍在。

## 2. 依赖的既有能力（全部复用，不重建）

| 能力 | 位置 |
|---|---|
| Plate 编辑器与选区 | `ChapterTextEditor.tsx` |
| 选区浮层 | `SelectionAIFloatingToolbar.tsx` |
| 候选生成与 Diff | `ChapterEditorDirectorPanel.tsx`、`useCandidateReview` |
| 候选接受/拒绝（含 CAS） | `useCandidateAcceptance` |
| 本地草稿与正式版本 CAS | `document/useChapterDraft.ts` |
| 运行与恢复 | `rightPanel/RunRecoveryTab.tsx`（P17.0.1 已按真实命令映射） |

## 3. 闭环的数据流

桌面端与网页端分开，入口函数相同、底层通道不同：

```
桌面端（Tauri）
选区(SelectionRange) → rewrite_chapter_selection 命令 → 受控 provider 路由(writer)
   → 候选文本 → 前端生成 id 与 diff（共享 buildChapterEditorDiffChunks）
   → Diff 预览(逐处选择) → 采纳 → 正文(contentDraft)
   → 保存(save_chapter + expectedVersion) → 章节正文

网页端
选区 → POST /novels/:id/chapters/:cid/editor/ai-revision-preview → 服务端 Prompt Registry
   → 候选(含 diffChunks) → 之后与桌面端一致
```

两端的候选稿形状（`ChapterEditorAiRevisionResponse`）与 diff 实现必须一致，否则采纳路径会报「对比不完整」。

## 4. 必须保证的安全约束

1. 候选确认走 `confirm_candidate_after_edit_run`，带 `baseCandidateId` + `baseContentSha256` + `expectedVersion`；
2. 保存走 `save_chapter` 的 `expectedVersion` CAS，冲突时提示刷新，绝不覆盖他人正文；
3. 未保存正文与候选稿在任何切换/关闭前都必须显式确认；
4. 所有模型请求只经受控 provider 路由，UI 不拼 endpoint，不使用付费模型。

## 6. 已知障碍（实测）

编辑位置恢复（滚动偏移）在 Tauri WebView 中未生效：
- sessionStorage 已正确写入（`chapter-scroll:{novelId}:{chapterId}` = 420）；
- 返回章节时容器可滚动（scrollHeight 5184 / clientHeight 657）；
- 但恢复后 `scrollTop` 仍为 0，三种实现（单帧、有界重试、跨帧重复写回）均失败。

因此该功能已**回退**，不留在代码里。下一轮应改用 React 层状态（例如在 Shell 记录段落锚点并调用 `scrollIntoView`，复用 `focusRange` 已有的滚动实现），而不是直接写 DOM `scrollTop`。

## 7. P17.1-a 的实际交付（2026-11-01）

原计划把 a 阶段当成「补一个 Mock 脚本就能验的 E2E」。实测发现桌面端这条链路本来就不通，补测试只会把坏链路固化下来，因此先修功能：

1. **桌面端没有改写路由。** `previewChapterAiRevisionWithRouting` 的云分支打 `/editor/ai-revision-preview`，`desktopApiAdapter` 没有这条路由，直接落到 `unsupported()`，返回 501「这个功能暂未接入桌面本地内核」。
2. **本地分支走错了通道。** 旧实现由 `localStorage` 的 `local-creation-mode:{novelId}` 控制，而该开关只在小说基础信息页出现，章节编辑页没有入口；即便打开，它调的是 `startGenerationAwaitCheckpoint` → `open_run`，那是整章导演流水线：忽略 `selection.text`，把作者的指令塞进 `promptVersions` 当版本号传，返回整章草稿当候选。

修法：

- 新增 `rewrite_chapter_selection` 命令（`src-tauri/src/commands/editor.rs`），只做一次受控模型调用，不建 Run、不写候选表、不动正文；
- 提示词按治理要求落在 `crates/novel-prompt`（`chapter_selection_rewrite` / `chapter-selection-rewrite-v1`），「只改选中片段」与候选数量写进模板本身，而不是只靠调用方参数约定；
- 路由判定改为 `hasDesktopShell()`，不再依赖作者看不见的 localStorage 开关；
- diff 实现收敛到 `shared/types/chapterEditor/document.ts` 的 `buildChapterEditorDiffChunks`，服务端改为从 shared 再导出。两套 diff 会让 `applySelectedChapterEditorDiff` 的重建校验失败，表现为采纳时整段报「对比不完整」。

坐标安全：编辑器坐标是 UTF-16，Rust 字符串是 UTF-8，中文正文下混用会错位。命令按 UTF-16 偏移取子串并与 `selectedText` 逐字比对，不一致就返回冲突，让作者重新选中，而不是猜要改哪一段。
