# P17.1 作者创作闭环设计

> 状态：设计已定稿，实现仅完成 P17.0.1 的缺陷收口（见 `P17.0.1-CODE-REVIEW-CLOSURE.md`）。本文件描述目标形态与依赖。

## 1. 目标

把「章节工作台」从导航 + 运行面板，推进到**真实创作闭环**：作者选中正文 → AI 改写 → Diff 预览 → 部分应用 → 保存 → 切章返回一致 → 重启仍在。

## 2. 依赖的既有能力（全部复用，不重建）

| 能力 | 位置 |
|---|---|
| Plate 编辑器与选区 | `ChapterTextEditor.tsx` |
| 选区浮层 | `SelectionAIFloatingToolbar.tsx` |
| 候选生成与 Diff | `ChapterEditorDirectorPanel.tsx`、`useCandidateReview` |
| 候选接受/拒绝（含 CAS） | `useCandidateAcceptance` |
| 本地草稿与正式版本 CAS | `document/useChapterDraft.ts` |
| 运行与恢复 | `rightPanel/RunRecoveryTab.tsx`（P17.0.1 已按真实命令映射） |

## 3. 闭环的数据流

```
选区(SelectionRange) → /chapter-editor/* 请求 → 本地 Mock LLM(provider registry)
   → 候选(chapter_candidate) → Diff 预览(选中变更) → confirm(候选 CAS)
   → 正文(contentDraft) → 保存(save_chapter + expectedVersion) → 章节正文
```

## 4. 必须保证的安全约束

1. 候选确认走 `confirm_candidate_after_edit_run`，带 `baseCandidateId` + `baseContentSha256` + `expectedVersion`；
2. 保存走 `save_chapter` 的 `expectedVersion` CAS，冲突时提示刷新，绝不覆盖他人正文；
3. 未保存正文与候选稿在任何切换/关闭前都必须显式确认；
4. 所有模型请求只经受控 provider 路由，UI 不拼 endpoint，不使用付费模型。

## 6. 已知障碍（实测）

编辑位置恢复（滚动偏移）在 Tauri WebView 中未生效：
- sessionStorage 已正确写入（`chapter-scroll:{novelId}:{chapterId}` = 420）；
- 返回章节时容器可滚动（scrollHeight 5184 / clientHeight 657）；
- 但恢复后 `scrollTop` 仍为 0，三种实现（单帧、有界重试、跨帧重复写回）均失败。

因此该功能已**回退**，不留在代码里。下一轮应改用 React 层状态（例如在 Shell 记录段落锚点并调用 `scrollIntoView`，复用 `focusRange` 已有的滚动实现），而不是直接写 DOM `scrollTop`。
