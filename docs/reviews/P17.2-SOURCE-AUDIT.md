## 审查发现的问题与修复

### 1. 桌面版「AI 优化这段」被 ACL 拒绝（严重，已修复）

**现象**：命令 `rewrite_chapter_selection` 已注册进 `invoke_handler`，进程内单元测试全绿，但真实窗口调用返回
`Command rewrite_chapter_selection not allowed by ACL`。点击「AI 优化这段」没有任何反应。

**根因**：Tauri 2 要求命令同时出现在三处：

1. `src-tauri/src/lib.rs` 的 `invoke_handler`；
2. `src-tauri/build.rs` 的 `commands` 清单（编译期生成 `allow-*` 权限）；
3. `src-tauri/capabilities/*.json` 的 `permissions`（运行时授权）。

`rewrite_chapter_selection` 只做了第 1 步。P17.1 的验证停留在 Rust 单元测试层，从未在真实窗口里调用过。

**修复**：补齐 `build.rs` 清单与 `default.json` / `e2e.json` 两套 capability；新增的
`list_pending_selection_rewrites` 一并登记。

**教训**：编译通过 + 单元测试通过 ≠ 真实窗口可用。已写入
`docs/wiki/debugging/recurring-failure-modes.md`。

### 2. 桌面版采纳候选永远写不进正文（严重，已修复）

**现象**：生成候选成功、Diff 面板正常，点「接受已选」后正文不变，无报错、无提示。

**根因**：`useCandidateAcceptance` 在写正文前调用 `POST /novels/:id/snapshots` 创建保护快照。
桌面适配器 `desktopApiAdapter` 没有这条路由，落到 `unsupported()` 返回 501，
整个 mutation 在 `updateNovelChapter` 之前就失败了。toast 未能可靠呈现，作者看到的是「点了没反应」。

**修复**：桌面适配器把该路由显式降级为「章节修订保护」的 no-op，返回一个标记为
`protectionScope: "chapter-revision"` 的对象。内核本来就用章节修订（`list_chapter_revisions`）
承担历史保护，不需要整书快照。

### 3. 选区改写计费状态不可见（中，已修复）

**现象**：超时、连接中断被统一报成普通失败，作者可以直接重试，可能重复计费。

**修复**：

- 新增 `AppErrorCode::MODEL_RESULT_UNKNOWN`，只有「可能已发送、结果不可确认」才使用；
- 新增 `chapter_selection_rewrite_attempt` 表（迁移 `0025`），记录 `not_sent` / `sending` /
  `failed` / `unknown` / `succeeded`，按 `novel_id + chapter_id` 隔离；
- 同一 `requestId` 在 `sending` / `unknown` / `succeeded` 状态下再次进入返回 `CONFLICT`；
- 前端 `chapterSelectionRewriteBilling.ts` 把错误归到 `never_sent` / `unknown` / `billed_failure`，
  重新生成前要求确认；章节里有未确认请求时，正文上方给出可见提示；
- 记录表只有 7 个字段（状态、时间、短原因），不含正文、提示词、端点或凭据。

**未做**：没有实现「跨进程自动对账」，也不做 exactly-once 承诺。未知状态保留为未知，
由作者显式确认后重试。

### 4. 长章节对比会耗尽内存（中，已修复）

**实测**：旧实现是完整二维 LCS 矩阵。1 万字约 2.4s / 630MB；3 万字与 5 万字在默认 2GB JS 堆下直接 OOM。
本机未通过放大堆掩盖问题。

**修复**：`buildChapterEditorDiff` 先按**码点**裁掉公共前后缀（不能按 UTF-16 单元裁，会把代理对劈开），
再在 400 万单元格预算内做精确 LCS（一维 `Int32Array`，内存约为原二维数组的 1/4）；
超预算退到段落级对齐，再超预算明确标记 `degraded: true` 整段替换。

**实测（修复后）**：1 万 / 3 万 / 5 万字的局部改写均为 3–5ms，`degraded: false`，改动量收敛在 10 个原文字符内。
结构完全不同的大文本会 `degraded: true`，分片仍能精确重建原文与候选。

`applySelectedChapterEditorDiff` 的「重建校验」原样保留：任何路径产出的分片都必须能逐字还原两边。

### 5. 跨章异步结果会污染当前章节（中，已修复）

**现象**：AI 请求进行中切章，晚到的候选或错误会写进**新章节**的会话状态。

**修复**：请求发起时记录章节（`previewChapterRef` / `continuationChapterRef`），
响应到达时用 `isResultForCurrentChapter` 比对；不一致就丢弃。成功与失败路径都覆盖。

### 6. 编辑位置在重启后丢失（功能缺口，已实现）

**修复**：新增 `editPosition.ts`：

- 按小说记录章节、光标 UTF-16 偏移、滚动像素、记录时的正式版本与正文长度；
- 记录只含坐标与标识，单测断言字段名集合，防止夹带正文或凭据；
- 恢复前必须等编辑器用当前正文重建完成；正文明显变短（不足原长一半）或坐标越界时放弃；
- 新增 `pointFromCursorOffset`（`getCursorOffsetFromValue` 的逆运算），对全部合法偏移做往返验证。

**产品决策**：应用启动**不自动跳转**，停在首页并由「继续上次写作」入口带回上次章节。
自动跳转会打断「先看整体进度」的常见动作，也会让未迁移接口在首屏被意外请求
（实测会让 `provider-no-missing-routes` 回归失败）。

## 未采用的做法

- **DOM 滚动恢复**：旧方案在 WebView 里无效（编辑器重建即重置滚动）。改为与光标同一条记录、
  在文档恢复后统一应用。
- **Phase 5 拆分 `ChapterEditorShell.tsx`**：当前 983 行，低于硬阈值 1300；本轮刚经历大量行为改动，
  为降低回归风险不做无行为理由的重排。若后续新增职责使文件超过 1300 行，再按
  AI 请求会话、候选审阅、保存/草稿、导航守卫拆分。
- **放大 Node 堆掩盖长文本 OOM**：会让问题在真实用户机器上更晚暴露。
