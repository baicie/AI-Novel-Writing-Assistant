# P16.6-R4 Director 多模型与冻结路由 HTTP 证据（C + D）

## 结论

- **C 通过**：四环节分别路由到两个独立 Mock Provider，Repair 由审校问题真实触发。
- **D 通过**：轮换密钥/端点/绑定后，旧 Run 的实际请求仍使用旧密钥、旧端点、旧模型；新 Run 使用新配置。

测试文件：`crates/novel-application/tests/p166_multi_provider_director_http.rs`
命令：`cargo test -p novel-application --test p166_multi_provider_director_http` → **2 passed, exit 0**

## C：四环节多 Provider

| 服务器 | 请求数 | 模型 | Authorization | 路径 |
| --- | --- | --- | --- | --- |
| A（planner/review） | 6 | model-plan ×4、model-review ×2 | `Bearer key-A` | POST /v1/chat/completions |
| B（writer/repair） | 2 | model-write ×1、model-repair ×1 | `Bearer key-B` | POST /v1/chat/completions |

装配：真实 SQLite + 真实 `ProviderService`（注册表 + 版本化密钥）+ `frozen_step_routes()`（单事务快照）+ `director.open_run` + `worker.tick()` + `OpenAiCompatibleProvider` → 两个本地 Mock Server。
流程：story_macro → character_cast（审批）→ volume_strategy（审批）→ chapter_list → draft → consistency_review（返回 high 级问题）→ bounded_repair → 再审校（通过）→ succeeded。

断言：两服务器都收到请求；A 只收 A 的模型与密钥；B 只收 B 的；四环节各至少一次；contract JSON 无密钥明文但含冻结引用 `gw-b#1`；SQLite 有 workflow_run 记录。

## D：轮换后旧 Run 的冻结路由

步骤与断言（全部基于实际 HTTP 记录）：

1. 打开 Run-Old，冻结四环节路由（writer → gw-b / model-write / B 端点 / gw-b#1）。
2. 推进到第一个业务暂停点（`waiting_approval`，legal_actions 含 approve/confirm）——**没有直接改 SQLite 状态**。
3. 轮换：A 换 `key-A → key-A2`；B 换 `key-B → key-B2` 且 Endpoint 改为第三个 Mock Server（B2）；writer 绑定改为 `model-write2`。换明文 HTTP 主机走了产品要求的显式确认参数 `upsert_provider_with_confirmation(..., true)`。
4. 断言旧槽仍在：`vault["gw-b#1"] == "key-B"`。
5. 放行旧 Run → 继续执行到 succeeded。

旧 Run 的实际请求断言：

- 所有 A 请求 `Authorization: Bearer key-A`（旧密钥）。
- 所有 B 请求 `Authorization: Bearer key-B`（旧密钥），且模型不是 `model-write2`。
- **B2 服务器请求数为 0** —— 旧 Run 没有打到新端点。

新 Run（第二章）：

- `frozen_step_routes()` 显示 writer → B2 端点 / model-write2 / gw-b#2。
- 实际请求：B2 收到 1 次，`Authorization: Bearer key-B2`，模型 `model-write2`。

## 测试过程中暴露并遵守的产品规则（不是放宽断言）

1. 明文 HTTP 端点换到不同 host:port 需要显式确认，否则被 `Validation` 拒绝——测试改为传确认标志，模拟用户同意。
2. 业务暂停点必须按 `legal_actions` 用真实 Director 命令推进（approve），不能跳状态。
3. 同一章节已完成后再次 open_run 会直接短路为 succeeded；因此新 Run 使用新建的第二章（真实业务语义：新 Run 写新章）。
4. 剧本不合规（cast 只有 2 人）会让 Run 停在 `paused` 且 legal_actions 仅 cancel——这是结构化校验的正确行为。
