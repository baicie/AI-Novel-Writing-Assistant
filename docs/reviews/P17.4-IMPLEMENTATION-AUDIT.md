# P17.4 实施审查

## 结论

没有发现 P0/P1。伏笔生命周期复用既有 `plot_thread` 作为唯一权威，新增事件表与因果边表
只记录历史与关系，没有第二套故事事实仓储，也没有新增后台模型调用。

## B1 伏笔生命周期

- `plot_thread.status` 是唯一生命周期字段：open/developing/resolved/deferred/abandoned/stale。
- 新增 `plot_thread_event` 追加记录 setup/develop/payoff/defer/abandon/recover，
  每次转换带章节、来源版本、证据、前后状态与 commandId。
- 写入复用 `verify_plot_source`：章节属于本书、当前正式版本匹配、证据存在、推进章节不早于埋设章节。
- `expectedVersion` CAS；同一 `commandId` + 请求哈希幂等返回，不同请求冲突。
- 章节改写后 `invalidate_story_facts` 在同一事务内把伏笔置为 stale；恢复必须提供新证据。
- 没有把「计划回收」写成 resolved：只有 payoff 动作且证据有效才设置回收章。

## B2 时间线

- `get_plot_workspace` 汇总 timeline_event、character_state、plot_thread_event，
  按章节顺序升序返回，带章节、卷、来源版本、证据与状态。
- 时间线读取上限 500，超出 `timelineTruncated=true`；不加载全书正文。
- 筛选在客户端完成（类型、伏笔、卷），数据规模有界。
- 严格区分叙事章节顺序与故事内部时间：当前没有可靠的故事内时间字段，只展示章节顺序，
  不推导精确日期。

## B3 剧情因果

- `plot_causality_edge` 只允许引用 `timeline_event` / `plot_thread` / `structured_fact`，
  且必须属于同一本书；引用不存在实体拒绝。
- 自引用拒绝；DFS 检测循环并返回明确冲突。
- 边必须有真实章节证据与来源版本；来源改写的边保留但 `sourceValid=false`。
- 本轮不生成 AI 因果建议，也不允许模型直接创建边；没有「模型推断直接成为正式关系」的路径。

## B4 章节工作台

- 新增「剧情线索」页签：伏笔卡片、按章时间线、因果边。
- 每条更新时间线/伏笔都带来源章节；跳转复用 `onOpenChapter`，由 Shell 的
  `leaveEditor` 处理未保存正文守卫。
- 时间线、来源、证据与状态都来自真实查询；空态明确说明，不伪造。

## B5 Director 上下文

- Context Assembly 的 `story_facts` 继续来自 `list_story_facts`；伏笔状态与证据按 As-Of
  事件推导，未来回收不会提前进入较早章节。
- 运行 context step 仍把 trace 写入冻结 artifact；历史 Run 的 trace 不随数据库变化。
- 没有新增模型调用；预算与排除原因沿用 P17.3 的 `ContextTrace`。

## 独立审查清单

| 检查项 | 结论 |
| --- | --- |
| 未来章节泄露到较早章节 | 否：story facts 与 plot threads 都按事件/章节顺序 As-Of |
| 旧证据错误重新确认 | 否：事实与伏笔都校验当前正文证据 |
| Worker 晋升留下过期故事状态 | 否：fenced 晋升事务内失效 |
| 伏笔回收是否需要人工确认 | 是：只有作者 transition payoff 才 resolved |
| 正常人物变化误判为矛盾 | 否：替换/延迟生效通过状态与事件表达，不当作冲突 |
| 章节重排破坏事件时序 | 投影重新评价来源顺序；违反顺序标为 invalid |
| 结构化事实与 plot_thread 双重权威 | 否：结构化事实仍走 structured_story_fact；伏笔唯一权威仍是 plot_thread |
| 跨小说写入 | 全部查询与写入带 novel_id，因果边校验同书 |
| 绕过版本 CAS | 事实/候选/冲突/伏笔/因果均带版本或唯一约束 |
| 修改冻结 Run 来源 | 否：只读冻结 artifact |
| 无界扫描/无界模型调用 | 章节 header + 上限查询；无后台模型调用 |

## 残余风险（P2）

1. 时间线只按章节顺序；没有可靠的故事内日期，不自动推导。
2. 因果边列表返回实体 ID 与标签，但没有复杂关系图可视化。
3. 旧 plot_thread 行没有事件历史，按当前状态回退展示；后续操作会补齐事件。
4. 伏笔动作要求当前章节证据；跨章补证据需要作者切到对应章节。
5. AI 不会主动建议伏笔推进或回收；这是本轮的有意边界。
