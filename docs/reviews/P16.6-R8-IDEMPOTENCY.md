# P16.6-R8 幂等性验收

> 生成时间：本轮 R8 执行期间；分支 `feat/p16-6-provider-hardening`；验收 HEAD `43a3c564`。所有数字均来自本次真实执行。

## 覆盖矩阵

| 场景 | 用例 | 断言 |
|---|---|---|
| 同一 command_id 重复确认 | `candidate_confirmation_is_idempotent_and_conflicting` | 第二次返回成功（幂等），正文只提交一次 |
| 同一 command_id + 不同内容 | 同上 | 返回 CONFLICT，正文与正式版本均不变 |
| 正式版本只递增一次 | 同上 | `official_version` 在重放后保持不变 |
| 确认不触发新模型请求 | 同上 | 请求数在确认前后完全一致 |
| 提交后崩溃再重放 | `crash_after_commit_keeps_content_and_replay_is_idempotent` | 重放幂等、版本不二次递增、0 次新请求 |
| 取消命令重放 | `unknown_billing_pauses_and_only_explicit_resume_retries` | 重放返回成功，请求数不变 |
| 恢复命令重放 | `explicit_regeneration_uses_a_new_attempt_and_replays_idempotently` | 重放后请求数不再增加 |

## 三类身份的区别（实现事实）

- `command_id`：业务幂等标识，落在本地命令记录，同 id 不同内容 → CONFLICT。
- `request_id` / attempt：一次发送尝试的身份，用量与审计按它累计。
- Run/Step 持久化状态：决定恢复动作是否允许重发。

第三方模型服务不保证 exactly-once，因此系统只承诺「本地不会因为重复命令而产生第二次有效提交或第二次计费未知的重发」。
