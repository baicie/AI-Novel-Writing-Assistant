# P17.3 实施审查

审查范围：`feat/p17-3-story-continuity` 相对 `beta` 的全部变更。

## 结论

没有发现 P0/P1。新增能力全部建立在既有结构化事实、记忆候选/冲突与 Director 上下文组装之上，
没有第二套记忆引擎或上下文组装器。

## 逐项检查

| 检查项 | 结论 | 证据 |
| --- | --- | --- |
| 是否重复构建已有记忆系统 | 否 | 只新增只读投影 `ChapterContinuityService`；写入仍走 `confirm_memory_candidate`、`resolve_memory_conflict`、`confirm_structured_fact` |
| 是否混淆 confirmed / proposed / disputed | 否 | 投影只把 `truthfulness=confirmed` 且来源版本有效的事实放进 `facts`；proposed/disputed 只进入冲突展示池；单测 `conflict_sides_expose_both_sources_without_auto_overwrite` 断言 disputed 不进入有效事实 |
| 是否泄露未来章节事实 | 否 | 所有查询带 `effective_chapter_order <= 目标章节顺序`；单测覆盖第 15 章看不到第 20 章死亡、第 5 章才可见 |
| 是否错误使用过期修订 | 否 | 结构化事实与来源当前正式版本比对：不同 → `stale`，来源缺失 → `unavailable`；单测覆盖章节重存后事实过期与重新确认 |
| 是否产生跨小说数据混用 | 否 | 所有查询带 `novel_id`；目标章节必须属于本书；单测覆盖两本书事实互不出现 |
| 是否绕过事实确认版本约束 | 否 | 候选确认沿用章节版本 + 内容哈希 + 候选版本 CAS；冲突裁决带 `expectedVersion` 与 `commandId`；界面只禁用，不绕过 |
| 是否修改历史 Run 的冻结上下文 | 否 | `get_run_context_trace` 只读该 Run 的 `context` artifact；E2E 在运行后新增事实，trace 与 artifact payload 均未变化 |
| 是否把未保存正文当作已确认事实 | 否 | 事实只来自 `structured_story_fact`、已确认候选写入的状态/时间线/伏笔；不读取编辑器内存或本地草稿 |
| 是否把模型推断当作确定事实 | 否 | 记忆抽取只产生候选；候选必须由作者确认；E2E 确认前候选存在，确认后才进入人物状态 |
| 是否引入无界上下文或无界查询 | 否 | 章节只读 header（不加载正文）；结构化事实 500 条、候选 200 条、冲突 100 条上限；界面限制 80 条关键事实；上下文预览硬上限 64k tokens |

## 数据流审查

1. `get_chapter_continuity` → 六类查询（章节 header、人物、世界、故事事实、结构化事实、候选、冲突）
   全部按 novel/chapter 过滤。
2. `list_structured_facts_with_source` 一次 JOIN 来源章节与当前正式版本；不静默丢弃过期行。
3. `visible_facts_at` 纯函数从存储层移到 application 层，仓储与投影共用同一 As-Of 规则。
4. `preview_chapter_context` 复用 `assemble_director_context`，返回 `ContextTrace` 与 `blockedReasons`，
   不返回 Prompt 正文。
5. `get_run_context_trace` 只解析 context artifact 的 `trace`，不读取当前数据库最新事实。

## 残余风险（P2）

1. 世界规则没有独立建模；面板只展示真实的世界名称、描述与概览，不伪造规则列表。
2. 旧故事事实（角色状态/时间线/伏笔）在章节重存后被标记 superseded 并退出有效集；
   界面只对结构化事实提供「重新确认」入口，旧故事事实需要重新抽取。
3. 记忆候选的证据来自候选表；如果没有对应候选（历史手工写入），来源章节可见但证据为空。
4. 候选/冲突/结构化事实超过上限时只显示最近部分，界面会提示截断。
5. 上下文预览依赖既有书籍产物；新书没有产物时显示阻断原因，不会生成空上下文。
6. Native E2E 使用本地 Mock LLM；真实厂商的 schema 漂移仍可能暴露新的兼容问题。
