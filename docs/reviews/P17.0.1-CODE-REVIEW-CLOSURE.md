# P17.0.1 源码审查门点收口

修复提交：`79b7b531`（分支 `feat/p17-0-authoring-workbench`，未推送）
审查对象：PR #7 的 `rightPanel/`、`navigation/` 与 Run 关联逻辑。

## Task 1 — Run Legal Actions 映射

**原问题**：`confirm_after_edit` 被当成普通确认、`regenerate` 走了 `resumeRun`、候选确认缺少 CAS 参数。

**对照真实 Director 取值**（`crates/novel-application/src/director.rs:908-928`）：

| 状态 | 后端 legal_actions |
|---|---|
| `waiting_approval` + gate | `confirm` / `reject` / `regenerate` / `confirm_after_edit` |
| `paused`（安全停点） | `cancel`（+ `resume_quality_debt`） |
| `paused`（普通） | `resume` / `cancel` |
| `running` / `queued` | `cancel` |

**修复后的映射**（`rightPanel/panelModel.ts`）：

| legal action | 渲染动作 | 真实 Tauri 命令 |
|---|---|---|
| `confirm`（章节确认门点且有候选） | 确认候选正文 | `confirm_candidate_after_edit_run` |
| `confirm`（规划门点无候选） | 确认这一步 | `approve_run` |
| `confirm_after_edit`（无候选） | 不渲染 | — |
| `reject` | 退回重写 | `reject_run` |
| `regenerate` | 重新生成 | `regenerate_run` |
| `resume` | 继续这次创作 | `resume_run`（`acceptCandidate:false`） |
| `resume_quality_debt` | 接受质量提醒并继续 | `resume_run_with_quality_debt`（带 reason） |
| `cancel` | 取消这次创作 | `cancel_run` |
| 未知动作 | **不渲染** | — |

候选确认必定携带 `baseCandidateId` + `baseContentSha256` + `content` + `expectedVersion`，不会用 `approve` 绕过正文 CAS。
成功后统一失效 `authoring-runs`、`authoring-run-detail`、novel detail、chapter workspace 四类缓存。

单测：`rightPanel/panelModel.test.mjs`（11 条，含「regenerate 不得退化为 resume」「无候选不渲染候选确认」「未知动作不渲染」）。

## Task 2 — 章节导航取消安全

**原问题**：「待处理」徽标嵌套在章节按钮里（非法嵌套交互元素），且取消后仍可能打开运行页签。

**修复**：

- 行结构与徽标改为并列的两个 `<button>`，`<li data-chapter-id>` 承载语义；
- 所有入口（行按钮 / 徽标 / 上下一章 / `Alt+←/→`）统一走 `chapterNavigationIntent(target, current, openRunTab)`：
  - 目标≠当前 → 先过 `shouldBlockChapterSwitch(isDirty || isBusy, confirm)`；被拒绝时**直接 return**，章节、页签、草稿、选择全部不变；
  - 目标=当前 → 只切页签，不需要确认；
- `isBusy` 覆盖「保存中」与「本地草稿写入失败」两种特殊状态。

Native E2E：`e2e/p17-cancel-navigation.e2e.js`（真实两章 + 真实 failed Run）
1. 第二章用 `execCommand("insertText")` 制造真实未保存状态（`data-local-draft-dirty="true"`）；
2. `window.confirm = () => false` 后点第一章「待处理」→ hash 不变、运行页签未激活、仍 dirty；
3. `window.confirm = () => true` 再点 → 跳到第一章且运行页签激活，显示该章自己的 Run。

## Task 3 — 章节导航数据模型

**原问题**：`ChapterNavGroup.chapters` 声明为 `Chapter[]`，实际塞的是 `as unknown as Chapter` 的简化对象，`content` 丢失。

**修复**：

- 新增 `ChapterNavItem`（`id/order/title/volumeId/officialVersion/wordCount/hasContent`）与 `toChapterNavItem`，删除全部 `as unknown as` 断言；
- 字数来自真实正文：`content.trim().length`；纯空白计 0、显示「空」；
- `formatWordCount` 与 `formatChapterWordCount` 同口径；
- 显示层测试覆盖：真实字数、纯空白、未分卷回退、卷顺序、搜索、相邻章。

## Task 4 — Run 与章节关联

**原问题**：本章没有 Run 时会回退到全书最新 Run，可能在 A 章界面操作 B 章的运行。

**修复**（`rightPanel/RunRecoveryTab.tsx`）：

- 只取 `run.chapterId === 当前章节` 的 Run；没有则显示 `data-testid="run-empty"` 的明确空态 + 「查看全书运行记录」入口；
- Query key 加入 `chapterId`（`["authoring-run-detail", novelId, chapterId, runId]`），快速切章时互相隔离；
- 详情必须 `detail.chapterId === chapterId && detail.id === latest.id` 才驱动界面，否则退回列表态并禁用动作 —— 旧响应无法覆盖新章节；
- 动作执行前校验存在性，成功后失效四类缓存。
