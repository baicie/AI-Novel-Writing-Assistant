# P17.4 Native E2E 验收

## 环境与隔离

- macOS arm64 原生 Tauri 应用，独立 `mktemp` 数据目录与独立进程。
- 真实 IPC、真实 SQLite；不调用任何外部模型，时间线/伏笔数据由 IPC 与真实保存动作产生。
- 保留 P17.2 / P17.3 的既有 spec 与双进程重启验证。

## 规格

| Spec | 用例 | 覆盖 |
| --- | --- | --- |
| `p17-4-plot-timeline.e2e.js` | 3 | 伏笔生命周期 As-Of、来源失效与重新选取证据、时间线筛选、因果边与循环拒绝 |
| `p17-3-context.e2e.js` | 4 | 运行上下文包含已确认伏笔/事件、冻结 trace、预览读取当前事实 |
| P17.2 / P17.3 其它 spec | — | 既有作者旅程与可靠性 |

### Journey 1：伏笔生命周期

1. 第一章埋设「玉佩」；
2. 第五章推进；
3. 第十章回收；
4. 打开第五章：状态「推进中」，时间线不出现第十章回收证据；
5. 打开第十一章：状态「已回收」，时间线出现第十章证据；
6. 每一步都展示来源章节与原文证据。

### Journey 2：证据失效

1. 改写第十章（回收来源）；
2. 打开第十一章，伏笔显示「来源失效」；
3. 用旧证据执行回收被拒绝，状态保持失效；
4. 输入第十一章的新证据后回收成功；
5. 历史事件与旧证据仍保留在事件表中。

### Journey 3：时间线与因果

1. 创建「得到玉佩 → 被追捕 → 逃入山门」三个事件；
2. 建立两条因果边；
3. 第三章工作台按类型筛选时间线，能看到三条事件；
4. 尝试建立 `事件三 → 事件一` 被拒绝（循环）；
5. 改写第一章后，因果边显示「来源已失效」。

### Journey 4：Director 上下文

1. 运行前确认结构化事实、伏笔与时间线事件；
2. 真实 Mock Run 的 Context Trace 包含 `structured_story_facts` 与 `story_facts`；
3. 冻结 prompt 中包含伏笔标题与事件正文；
4. 运行后新增事实，旧 Run 的 trace 与 artifact payload 不变；
5. 新的上下文预览读取更新后的当前事实。
