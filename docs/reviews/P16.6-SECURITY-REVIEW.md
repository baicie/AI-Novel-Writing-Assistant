# P16.6 安全复审

范围：模型地址解析与出站、凭据存储与轮换、Run 路由冻结。
结论口径：只写有代码与测试支撑的结论；未验证项写明未验证。

## 1. 出站地址安全（SSRF / DNS Rebinding）

| 项 | 现状 | 判断 |
| --- | --- | --- |
| 明文 HTTP 是否可任意使用 | 需 `allow_localhost_http` 且绑定主机，换主机要二次确认 | 通过 |
| metadata / link-local 地址 | `authorize_endpoint` 始终拒绝 | 通过 |
| DNS 解析后目标校验 | `authorize_resolved_endpoint` 在**拼好最终 URL 之后**执行，校验的是真实请求主机 | 通过（本轮把校验点移到最终 URL） |
| 重定向 | reqwest 默认不跟随重定向（未显式开启），重定向不会把请求带去未授权主机 | 通过 |
| 非 http(s) 协议 | 新增 `base_url` 校验只接受 http/https，且有主机名 | 通过（用例 `invalid_endpoints_are_rejected`） |
| 查询参数/锚点 | 直接拒绝，避免把参数拼进路径后绕过规则 | 通过 |

## 2. 真实请求路径（避免打到错误主机或错误网关路径）

修复前：生成请求直接 POST 到 baseURL（`/v1`），真实网关返回 404，但**请求仍然发到了正确主机**，所以这不是信息泄漏问题，而是可用性问题。

修复后：`request_url::generation_url` 是唯一路径构造点；发现模型走 `models_url`，两者都不接受带查询参数的地址，也不会把 `..` 之类的路径段带进最终 URL（`url::Url::set_path` 规范化）。

## 3. 凭据存储

| 项 | 现状 |
| --- | --- |
| 密钥正文是否可能出现在 API/JSON/日志/事件 | 否：`ProviderView`、`FrozenStepRoute` 只带引用名；已有用例断言序列化结果不含密钥 |
| 密钥槽是否可变共享 | 否：槽位名 = `{provider}#{revision}`，清除为 `...#cleared`；旧槽永不覆盖/删除 |
| CAS 失败是否会破坏旧配置 | 否：先写新槽，提交失败即删新槽（`cas_failure_keeps_old_secret_and_profile`） |
| 历史 Run 是否会被换钥 | 否：合同冻结旧引用，旧槽保留（`replace_moves_to_new_slot_and_keeps_old_for_runs`） |
| 文件权限 | 写敏感字节前即 0600（临时文件 + rename） |
| 主密钥丢失 | 目录已有密文时拒绝重建，避免「旧密文永久解不开还继续写新数据」 |
| 文件名碰撞 | 清洗改名时追加 SHA-256 前 4 字节；旧文件名仍可读（升级兼容） |
| 读取权威 | 本地加密文件为准，钥匙库仅历史副本兜底 |

## 4. 明确未解决（不得当作已解决）

1. **frozen_step_routes 的一致性快照**：并发保存配置时，逐条 binding 解析可能拼出混合版本。影响：新 Run 可能拿到「A 的模型 + B 的推理强度」这类组合，但不会跨 provider 串用密钥（槽位仍按 provider 隔离）。
2. **legacy 密钥回退过宽**：缺 `credential_ref` 的合同会回退到 `contract.provider` 作槽位名；若历史数据里该值是别人写进去的，理论上可能读到非预期槽位。当前风险限于历史数据，新合同都带引用。
3. **Ollama 无密钥策略未显式化**：目前实现就是不鉴权；如果用户把 Ollama 协议指向远程主机，请求会以无鉴权方式发出。计划改为「仅回环地址允许空密钥」。
4. **密钥槽 GC**：旧槽保留策略安全但会累积（每个 provider 每次换密钥 +1 条）。需要「只保留最近 N 个 + 被活跃 Run 引用的」的回收策略。
5. **磁盘级攻击**：主密钥是 0600 文件，能解密全部密钥；这是既定取舍，不是本轮修复对象。

## 5. 复审结论

本轮修复把「配置成功却无法生成」（P0 可用性）与「换密钥毁掉旧配置/旧 Run」（P0 数据完整性）两条闭环，并顺带修掉三条密钥落盘加固项。安全语义未被削弱：新增断言全部是加强断言（例如未知协议必须零请求）。
