## P2（可带风险合并）

| 编号 | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | `StorageCorrupt` 历史偶发未复现 | 极端情况下用户看到「本地资料暂时没有写完」 | 已改为显式可重试错误；保留观察。本轮新发现并修复了一例测试侧临时目录释放导致的同类报错，但**不声称生产根因已定位** |
| R2 | 凭据槽无 GC | 磁盘上历史槽只增不减 | 仅保留 ciphertext；已在 `docs/design/P16-CREDENTIAL-LIFECYCLE.md` 记录后续回收方案 |
| R3 | 补偿回滚会让 `revision` 前进 | 前端若用旧 revision 提交会得到 Conflict | 已返回明确提示「创作进度已经变化，请刷新」；前端按最新 revision 刷新 |
| R4 | 第三方模型不保证 exactly-once | 跨网关重放可能重复计费 | 系统只承诺本地不重复提交、不擅自重发；文档已明示边界 |
| R5 | 生产 updater 配置为空（`pubkey:""`、`endpoints:[]`） | 桌面端无自动更新 | 与发布流程解耦；发布走 `tauri-release` 的 tag 流程，需要时再配置签名 |
| R6 | 单文件规模 | `workflow.rs`、`run.rs` 较大 | 未在本轮扩张；后续按架构规则拆分 |

## 发布路径风险检查

- `tauri-ci.yml`：仅 `pull_request` / `workflow_dispatch` / `workflow_call` 触发 → 推分支不会触发发布。
- `tauri-release.yml`：`push: tags: tauri-v*` 或手动；且 `updater-signed` 仅允许 tag 触发。
- `desktop-release.yml`：`push: tags: v*`（排除 `-dev.`）/ `desktop-v*`。
- `desktop-beta-release.yml`：`push: tags: desktop-beta-v*`。
→ **只要不推送 tag，合并到 beta 不会产生公开 release**。

## 合并后验证计划

1. 在 `beta` 上重跑 `cargo test --workspace` / `pnpm e2e`（本地或 CI）。
2. 用旧版本数据库副本启动一次，确认迁移 0022–0024 就位且旧 Run 停在安全点。
3. 手动冒烟：新建来源 → 绑定 → 发起章节生成 → 确认候选 → 正文落库。
4. 观察 24h 内是否出现 `StorageCorrupt` 报告。
