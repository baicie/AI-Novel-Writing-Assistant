## 为什么必须隔离运行

`e2e/wdio.conf.js` 的多个 spec 共用同一份应用数据：
它们是同一个应用进程里的连续会话，前一个 spec 写入的模型来源、章节草稿、
本地偏好会残留到后一个 spec。

实测未隔离时：11 个 spec 中有 2–5 个失败，且失败点固定落在
「上一个 spec 改过的状态」上（例如 `p17-cancel-navigation` 把 writer 绑定指向死端口后，
`p17-selection-rewrite` 拿不到 mock 路由）。

`scripts/run-p172-e2e-isolated.sh` 为每个 spec 分配独立 `mktemp` 数据目录、
重新拉起应用、结束后删除目录。这样失败一定属于该 spec 本身。

> 注意：`BIZ_NOVEL_DATA_DIR` 只隔离 SQLite；WebView 的 `localStorage` 仍属于应用用户数据目录。
> 位置恢复相关 spec 在 `before` 里显式清掉 `ai-novel:edit-position:*`，避免跨运行串书。

## 选区改写旅程（`p17-selection-rewrite.e2e.js`）

全程真实 IPC、真实 SQLite、真实编辑器选区；模型请求落到用例内起的 `127.0.0.1` mock 服务。

1. 通过 IPC 建书、建两章并保存正式正文；
2. 写入模型设置并校验 `writer` 路由确实指向本用例 mock；
3. 打开真实章节编辑器，在正文里用真实 DOM 选区选中一段；
4. 点「AI 优化这段」，等待 2 个候选；
5. **断言**：mock 恰好收到 1 次请求，提示词含选区原文与前后文，模型名正确；
6. **断言**：正式正文未被改动（直接读 `get_chapter`）；
7. 取消部分勾选后采纳，**断言**：被勾选的改写进入正文，未勾选的候选文案不出现；
8. 保存后切到第二章再返回，**断言**：正文一致、第二章未被写入；
9. `browser.refresh()` 后重新进入，**断言**：正文与正式版本不变；
10. 连点「AI 优化这段」，**断言**：请求数仍只加 1（进行中按钮禁用生效）。

> 说明：全程不使用 SQL 直接改正文，所有写入都经过界面或官方 IPC 命令。

### 进程级重启（`p17-selection-rewrite-restart.e2e.js`）

`browser.refresh()` 只能证明 WebView 重新加载，不能证明「关掉应用再打开」。
`scripts/run-tauri-p172-rewrite-restart-e2e.sh` 用同一个数据目录跑两次真实 app 进程：
第一次写入并保存，第二次只读校验正文、正式版本与编辑器展示一致。
本机执行结果：`1 passing`。

## 编辑位置恢复（`p17-edit-position.e2e.js`）

1. 打开第一章，用真实鼠标点击正文并用方向键移动光标，触发位置上报；
2. 切到第二章再切回，**断言**：偏好里有该章记录，坐标在正文范围内，编辑器里有真实光标；
3. 跳回首页，**断言**：出现「继续上次写作」入口，href 指向该章；点开后正文正确；
4. 把第一章正文改短，再切回，**断言**：内核正文已是新版，记录坐标不超过正文长度，
   界面不会因为旧坐标出问题。
