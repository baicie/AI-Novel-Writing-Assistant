## 关键设计决策

### 1. Trait-Based 处理器设计

**决策**: 使用 Rust trait 而不是宏生成处理器

**理由**:
- 类型安全在编译时检查
- 每个处理器可独立扩展
- 易于单元测试
- 易于理解和维护

**收益**:
- 0 个运行时错误
- 完整的 IDE 支持
- 清晰的职责分离

### 2. 多环境配置管理

**决策**: 使用预定义的配置对象而不是单一的全局配置

**理由**:
- 开发、测试、生产环境需求不同
- 配置在编译时类型检查
- 易于扩展新环境

**收益**:
- 配置错误在初始化时捕获
- 不同环境可独立运行
- 开发/测试互不干扰

### 3. 轻量级元数据跟踪

**决策**: 简单的计数器而不是复杂的性能分析

**理由**:
- 最小化性能开销
- 支持核心监控需求
- 易于扩展到更复杂的指标

**收益**:
- 低延迟开销
- 实时可用
- 易于与监控系统集成

### 4. 按工作流分组测试

**决策**: 将测试按业务流程分组（小说→章节→运行）

**理由**:
- 反映实际的用户工作流
- 易于理解测试意图
- 易于定位功能缺陷

**收益**:
- 测试组织清晰
- 易于维护和扩展
- 易于新开发人员理解
