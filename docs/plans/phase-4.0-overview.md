# Phase 4.0 - 实现与集成规划

**版本**: 1.0-draft  
**日期**: 2026-10-20  
**目标**: 从架构验证到实现，完成完整的端到端应用

---

## Phase 4.0 概述

Phase 4.0 是从 Phase 3.0 架构验证向实现演进的关键阶段。如果 Phase 3.0 是"设计蓝图"，那么 Phase 4.0 就是"真实建筑"。

### Phase 4.0 的目标

1. **Web 框架实现** - 将架构框架与 actix-web 或类似框架集成
2. **数据库集成** - 实现持久化层，连接到真实数据库
3. **功能完整** - 所有 13 个端点的实际实现
4. **性能准备** - 性能测试、优化、监控
5. **生产就绪** - 部署脚本、文档、安全加固

### 为什么分 Phase 3.0 和 4.0？

| 方面 | Phase 3.0 | Phase 4.0 |
|-----|----------|----------|
| 焦点 | 架构验证 | 实现交付 |
| 风险 | 架构是否正确 | 集成是否顺利 |
| 测试 | 单元/集成测试 | 端到端测试 |
| 输入 | 需求和设计 | Phase 3.0 的架构 |
| 输出 | 可测试的框架 | 可运行的应用 |

## Phase 4.0 包含的 5 个任务

### Task 4.1: Web 框架集成 (6-8 天)

**目标**: 选择和配置 Web 框架，实现所有端点

**为什么是 actix-web**?
- 性能最好 (Rust Web 框架中最快)
- 异步/await 原生支持
- 中间件生态完善
- 与 Phase 3.0 架构兼容

**工作范围**:
```
1. 项目配置
   - Cargo.toml 依赖 (actix-web, tokio, serde)
   - 编译配置

2. 基础应用
   - App 启动和配置
   - 路由注册
   - 中间件堆栈

3. 端点实现
   - 小说端点 (6 个)
   - 章节端点 (5 个)
   - 运行端点 (2 个)

4. 集成测试
   - HTTP 客户端测试
   - 端到端验证
   - 错误响应测试

5. 文档
   - API 端点列表
   - 请求/响应示例
   - 集成指南
```

**预期成果**:
- 13 个可工作的 REST 端点
- ~1,200 行 actix-web 代码
- HTTP 端到端测试
- API 文档

**风险评估**:
- 低风险 (Phase 3.0 架构已验证)
- 中等复杂度 (异步处理、中间件)

### Task 4.2: 数据库集成 (8-10 天)

**目标**: 实现 Repository 层，连接到 SQLite/PostgreSQL

**为什么分离 Repository**?
- 解耦业务逻辑和数据存储
- 支持多种数据库
- 便于单元测试 (可以 mock)
- 遵循依赖倒置原则

**工作范围**:
```
1. 数据库设计
   - Schema 设计 (novels, chapters, runs 表)
   - 索引策略
   - 约束和关系

2. 迁移工具
   - sqlx-cli 集成
   - 迁移脚本编写
   - 版本管理

3. Repository 实现
   - Novel 查询和保存
   - Chapter 操作
   - Run 状态管理

4. 连接池
   - 连接配置
   - 池大小优化
   - 重试策略

5. 事务支持
   - 多表操作事务
   - 错误回滚
   - 锁定策略

6. 测试
   - Repository 单元测试
   - 集成测试 (真实数据库)
   - 性能测试
```

**数据库 Schema 预览**:
```sql
-- 小说表
novels (
  id, title, author, description, 
  created_at, updated_at,
  status, version
)

-- 章节表
chapters (
  id, novel_id, title, sort_order,
  content, status, 
  created_at, updated_at,
  version
)

-- 运行表
runs (
  id, novel_id, chapter_id, type, status,
  result, error,
  created_at, updated_at,
  version
)

-- 可选表
users (id, name, email, created_at)  -- 多用户支持
```

**预期成果**:
- 完整的数据库 schema
- ~1,500 行 Repository 代码
- 数据持久化测试
- 迁移脚本

**风险评估**:
- 中等风险 (数据库设计需要谨慎)
- 需要充分的集成测试

## Phase 4.0 技术栈

### 已确定的技术

从 Phase 3.0 继承:
- **语言**: Rust
- **构建**: Cargo
- **测试**: tokio::test
- **应用核心**: 自建架构 (Phase 3.0)

### 新增技术决策

| 层级 | 技术 | 理由 |
|-----|------|------|
| Web | actix-web | 性能最好，异步支持 |
| 数据库 | SQLx | 编译时 SQL 检查，安全 |
| ORM | sqlx | 与 SQLx 一体化 |
| 日志 | tracing | 结构化日志，分布式追踪 |
| 监控 | Prometheus | 行业标准，Grafana 支持 |
| 容器 | Docker | 标准部署方式 |
| API 文档 | OpenAPI 3.0 | 标准接口描述 |

### 可选技术 (未来考虑)

- **缓存**: Redis 或 in-memory 缓存
- **队列**: Tokio mpsc 或消息队列
- **搜索**: Elasticsearch (如果需要全文搜索)
- **分析**: DataDog 或 New Relic
