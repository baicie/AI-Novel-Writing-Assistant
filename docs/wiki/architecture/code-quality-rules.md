# 代码质量审查规则（本项目落地版）

这份规则是本轮质量治理实际使用的判定标准：先按它找问题，再按它决定「能顺手修」还是「必须单开一轮」。

## 一、行为等价优先

1. 质量治理不改变产品行为：公共导出路径、函数签名、返回值形状保持不变；改名用「新名 + 旧名再导出」过渡。
2. 每一步都要能跑同一组门禁（见第八节），失败就地回滚，不把红的状态留在分支上。
3. 纯结构搬动要求「函数体逐字不变」，只允许改 import 与可见性；改逻辑必须单独一次提交并带新测试。

## 二、模块边界与依赖方向

1. 组件层不得反向依赖页面层（`components/**` 不 import `pages/**`）；共用纯函数放 `platform/` 或 `domain/`。
2. 同名规则只能有一份实现：同一判定出现两处正则/两份映射，视为缺陷，收敛到单一模块。
3. 复用面广的模块用再导出保持兼容，不允许为了「看起来干净」一次性改掉所有引用。

## 三、文件规模

1. 目标 1200 行，警戒 1000 行，**硬线 1300 行**；越线必须先拆分再扩展功能。
2. 拆分按职责（错误/契约、纯映射、编排、适配器）落地，不按行数硬切；拆完要给出每个新模块的一句话职责。
3. 拆出的测试必须仍在同一次 `cargo test` 里被执行——「测试文件搬走了但没被编译」属于事故，提交前必须看用例总数有没有变化。

## 四、命名与语义

1. 语义变了就改名；名字与行为不符比名字难看更危险。
2. 迁移期保留旧名再导出，并在再导出处注明「过渡别名」。

## 五、错误处理

1. 禁止静默吞错：`let _ =` / 空 `catch` 只允许出现在「明确可以忽略」的场景，并且必须留日志或注释说明为什么可忽略。
2. 用户可见的失败必须带机器码（`code`）与可执行提示，便于用户自助判断。
3. 后台副作用失败不得阻断主流程，但必须留痕（例如注册表同步失败只记 warn）。

## 六、安全约束

1. 密钥只存引用，写入后必须回读校验；读不回来要有明确回退路径，而不是「写成功」的假象。
2. 明文 HTTP 只有在用户显式允许时放行；元数据与链路本地地址始终拒绝。
3. 任何「放宽安全」的改动都要在代码注释与文档里写明放宽的边界。

## 七、文案与文档

1. 用户可见文案只解释「能做什么 / 下一步是什么」，不写变更叙述。
2. 发布说明按日期合并，README 只保留最新日期块 + 历史链接。
3. 契约类知识（路由、强度、恢复规则）进 `docs/wiki/`，审查结论与取舍进 `docs/design/`。

## 八、门禁清单

| 检查 | 命令 | 期望 |
| --- | --- | --- |
| 格式 | `cargo fmt --all -- --check` | 无 diff |
| 静态检查 | `cargo clippy --workspace --exclude novel-http --lib -- -D warnings` | 通过 |
| 后端测试 | `cargo test -p novel-application --lib`、`cargo test -p novel-llm --lib`、`cargo test -p novel-desktop --lib` | 全绿，且用例数不低于改动前 |
| 前端类型 | `pnpm --filter @ai-novel/client typecheck` | 通过 |
| 前端测试 | `pnpm --filter @ai-novel/client test` | 全绿 |
| 真机行为 | `e2e/*.e2e.js`（需要时） | 断言可执行结论，不靠截图判断 |

## 九、判定分级

- **必须修**：违反硬线（超 1300 行）、门禁红、静默吞错、安全回退缺失、文案违规。
- **应当修**：命名与语义不符、规则重复两份、组件反向依赖、缺纯函数单测。
- **记录待办**：需要产品决策（放宽安全边界、档位白名单）或需要配套迁移（加密存储、大模块拆分）。
