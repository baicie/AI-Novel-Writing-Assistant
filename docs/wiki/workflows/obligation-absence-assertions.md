# 义务违反的缺席断言需要可证伪

## 背景

章节审校（Reviewer）有两类判定：

1. **矛盾类**：正文写了与义务相反的内容（例如义务要求「在场目击」，正文写成「到达时人已死」）。
   这类判定可以指向具体句子，前提是「我读到了这句话」。
2. **缺席类**：正文缺少义务要求的内容（`missing_element` / `omitted_required_event`）。
   这类判定的前提是「我在全文里没有找到」。

第 2 类的判断比第 1 类脆弱得多。Beta-A2 M1 复测中出现过一次实证：

- 义务 `ch1-req-01` 要求「在废井旁拾玉，遇雪不冷，贴近炉火浮出微光纹路」；
- Reviewer 报 high，type=`missing_element`，suggestion 要求「确保废井地点要素在正文中出现」；
- 而正文**首句**就是「林动在废井边捡到一块暖玉」，全篇「废井」出现 4 次，
  另外两项要求也都已写出。

结果：这条义务在初稿里本就满足，修复只是补了三处措辞，复验自然通过。整条
「审校 → 修复 → 复验」链路跑通，但**没有验证到任何真实的修复能力**。

现有确定性防线（evidence 必须逐字来自当前候选正文）**挡不住这一类错误**：那条 evidence
确实逐字存在，也确实位于相关段落。**证据可定位 ≠ 断言为真。**

## 决策

把「缺席」当成一个需要举证的断言，而不是默认成立的事实。

- 审校输出保持 AI-first：判定仍由 AI 给出，不引入关键词兜底来判断「某个要素在不在」。
- 但在契约层要求审校**说明它检索了什么范围**，并由确定性代码提供一个可反驳的通道：
  如果义务要求的关键要素在正文/上下文中确实存在，则该 `missing_element` 判定不成立。
- 两类问题分开处理：`contradiction`（找到反例）默认可信度高；`missing_element`
  （没找到）需要更强的证据或更低的默认严重度。

## 当前规则

- 新增或修改审校 schema 时，`missing_element` 必须携带：
  - 已检查范围（正文全文、上下文来源）；
  - 缺失的具体要素（不是「不够好」，而是「义务里的哪一项没有出现」）。
- 确定性代码可以对**结构化要素**做存在性核对（例如义务里点名的地点名、参与者名是否出现），
  这属于「对已结构化 AI 输出的确定性后处理」，允许；不得用它替代 AI 的语义判断。
- 缺席类问题不得单独构成「一次修复收敛」的证据。验收报告里若要声称 Repair 能力，
  必须说明被修的问题在修复前**确实成立**。
- 章节审计与自动导演链路的非阻断规则不变：这类误判只会产生一次无意义修复，
  不会升级成 replan 或全局失败。

## 示例

反例（Beta-A2 M1 实际发生）：

```text
义务：ch1-req-01 在废井旁拾玉、遇雪不冷、炉火显纹
审校：high / missing_element / evidence「他蹲下去，扒开雪。」
建议：确保废井地点要素在正文中出现
事实：正文首句「林动在废井边捡到一块暖玉」，全篇「废井」4 次
结论：前提为假；该义务已满足
```

正确做法：要求审校给出缺失要素清单与检索范围；确定性核对发现要素存在时，
把该判定降级为「审校存疑」，不触发修复，也不计入收敛证据。

## 失败模式

- 自动化门禁全绿，但审校在为一个不存在的缺口提意见 → 修复消耗 token 却不改任何实质内容。
- 把这种「跑通」写进验收报告，导致 Repair 能力被高估。
- 用关键词兜底去判断「要素在不在」来修这个问题 → 违反 AI-first 规则，且换成同义词就失效。
