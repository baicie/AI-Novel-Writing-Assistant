## 1. 站得住的部分

**凶案场景的物理调度**是全章最强的一段。作者没有直接写「林动很害怕」，而是把恐惧放进
空间约束里：他先说「他熟悉铁匠铺的每一道缝」并交代炉子、铁砧、大风箱的相对位置
（47 行），再写「风箱挡住了他半边身子。他从风箱和墙的缝隙里看出去」（49 行）——视角被
限死在一个缝里，读者只能和他一起看见那一线画面。凶手逼近时靴尖停在风箱前、拨开麻袋、
废铁料哗啦响（91 行），威胁是逐步逼近的，不是一句话宣布的。

**细节替代抒情**用得克制。开篇「掌柜嫌他送得晚，扣了两枚铜钱。他没争」两句交代了
贫穷、性格和处境，没有形容词。逃亡段「一脚踢翻了晒炭的竹席。黑炭滚了一地，在雪上格外
显眼」是全章最好的一拍：主角在恐惧中做错了一件事，而这件事差点害死他。新手向的作品
尤其需要这种「选择带来后果」的段落。

**神秘感控制得当**。全章没有出现后续章节的任何一个名字（`玄霄宗`、`沈砚`、`灰衣楼`、
`断雪` 出现次数均为 0），只留了账册、炉号、「藏了二十年」三样东西与一句「藏好」。
这是第 1 章该有的分寸。

**首尾呼应**成立：开篇的「暖玉」与结尾的「暖得发烫」闭环，结尾的脚步声回到铁匠铺的
声音母题。

## 2. 需要处理的问题

### 2.1 灰衣人的离场动机不成立（最重要）

91 行：凶手搜完尸、没找到东西，**「转身朝风箱这边走来」**，拨开麻袋，手停在半空，
「随后从风箱旁提起那盏油灯」；接着「外面的雪压断了树枝，‘咔嚓’一声」，他转头、
收回手、走了出去。

三个问题叠在一起：

1. **提油灯没有用途**。读者会期待他要点火或照风箱后面，但油灯此后再未出现——虽然后文
   铁匠铺确实起火（「火舌从窗纸里舔出来」），文本却没有把这两件事连起来。
2. **树枝折断不足以让一个刚杀人的职业凶手离开**。他已经明确怀疑铺子里有人（他走到风箱
   前了），一声树枝响只会让他更警觉，不会让他放弃检查。
3. 他 10 秒后折返、看到脚印、踹门追人——**折返是对的，反而证明离场那一步是假的**。

这是全章唯一的因果断点，也是「一次修复」没有碰过的部分。可行改法（择一）：

- **让他带着账册离开去核查屋外**：他已经说过「井边我找过了，桥下也没有」，可以写他
  忽然想起什么、要亲自去看井台，油灯顺手提走用于照雪地。
- **让他为纵火离开**：他去取火油/引火物，回来时顺手点火，火与油灯、与后文的「走水了」
  三处就串成一条线。
- **让他听见第二声、更明确的动静**（不只是树枝），并且这个动静来自屋外雪道——
  给「离开」一个比「离开」更强的理由。

### 2.2 比喻是铁匠意象的单一种植

全章 14 个比喻句，其中 **8 个**明确落在锻造/金属意象上：`像细铁砂`（雪粒）、
`像有人在井底吹风箱`（井里的风声）、`像刚从炉边拿起来的铁片`（玉的暖意）、
`像铁坯烧透后浮起的锻纹`（玉纹）、`像灰里没熄的火星`（亮起的星点）、
`像铁锤敲在冷砧上`（凶手的声音）、`像铁片刮过石头`（凶手的笑）、
`像铁锤一下一下，敲在冷砧上`（结尾的脚步）。若把「炉号，像被火燎过」也算入则为 9 个。
全章「铁」字出现 40 次、「炉」16 次、「砧」5 次。

对铁匠学徒的视角来说，用锻造词汇感知世界是合理的，但 8/14 的比例已经从「人物视角」
滑向「作者的修辞习惯」。开头与结尾用**几乎同一句比喻**——41 行「像铁锤敲在冷砧上」→
149 行「像铁锤一下一下，敲在冷砧上」。这显然是有意呼应，但正因为中段又用了六次同类
意象，读者读到这里只会觉得「又说了一次」，收不到回环的效果。

建议删改 3–4 处，优先动 41 行（让凶手声音用别的质感，把「铁锤敲冷砧」留给结尾独占）。

### 2.3 「他熟悉……」框架用了两次，且句式相同

- 47 行：「他熟悉铁匠铺的每一道缝。前堂左边是炉子，右边是铁砧，最里面靠墙立着大风箱。」
- 129 行：「他熟悉这条巷子。左边是炭棚，右边是废井。」

两处都是「他熟悉 X。左边是……右边是……」。「主场救了他两次」这个设计是好的，但第二次
照搬第一次的句法，读起来像模板。第二次发生在逃命途中，应该更短、更碎，甚至可以写成
他一时想不起来——那样更紧张，也更真实。

### 2.4 生理反应拍有清单感

`他屏住呼吸`（33 行）、`林动的心猛地一跳`（59 行）、`林动咬住了自己的手背`（83 行）、
`林动的呼吸停了`（89 行）、`指尖都在抖`（63 行）——每一拍单看都有效，但它们的间隔几乎
均匀，像按节点铺的情绪标记。加上「咬手背」「屏住呼吸」都是悬疑场景的通用动作，读者的
代入感会打折。

改法不是把这些全删，而是**让其中一两处换成选择或误判**：他伸手去够火钳、他差点喊出
声又咽回去、他以为凶手走了而挪动了半寸。已有的「踢翻竹席」就是这一类，属于全章最好的
示范，值得在凶案现场也用一次。

### 2.5 两处小的一致性摩擦

- **怀里 / 衣袋**：`揣进贴身的衣袋`（23 行）→ `他怀里的玉佩`（63 行）→ `按住衣袋`
  （63 行）→ `怀里的玉佩`（141 行）。同一位置两种叫法交替，读者会短暂怀疑是不是两处。
  统一成一个。
- **「前堂到后窗的雪地上」**（119 行）：这是室内地面，写成「雪地」会让读者先想到屋外。
  改为「前堂到后窗的地上有雪，雪上是林动的脚印」之类，把「为什么室内有雪」交代清楚
  （后窗开着、雪吹进来）。

### 2.6 老铁匠的遗言偏模板

「走……」「别……别回头」「玉……别给他们……」「藏好」四句全是垂死导师的标准台词。
这个人物的特殊性在于：他把玉扔在井边、在镇上守了二十年、见到玉时「退了一步」。
遗言里没有一个字接住这二十年。

可以让他说一句**具体的、甚至是错的**话——认错了凶手、说了一个只有后文才解释得通的词、
或者坦白「我早该给你」。牺牲一点清晰度，换这一场戏的分量。这属于建议，不是缺陷。

### 2.7 开篇是总结句

3 行：「雪落镇封山第七天，林动在镇西废井的井台旁捡到一块暖玉。」这一句把整场戏的
结果先说完了，再倒回去写过程。网文的快速阅读习惯容得下这种写法，但和正文其余部分的
沉浸式笔法不一致。

值得注意的是：**这句话是被「修复」改过的**——初稿是「林动在废井边捡到一块暖玉」，
修复后变成「在镇西废井的井台旁」，句子的总结感更重了。见下节。

### 2.8 一处逻辑残留（与 2.1 同源）

灰衣人离场时「从风箱旁提起那盏油灯」（91 行），此后再未出现；而铁匠铺最终起火
（135 行「走水了」）。文本既没说火是怎么起的，也没让油灯参与其中。读者会自然把两者
联系起来，于是「他提着灯走了」变成「他带走了纵火工具又回来了」——这在逻辑上说得通，
但作者从头到尾没有确认过这层关系。要么让它成为明写的伏笔，要么删掉油灯这个动作。

## 3. 流程发现：这次的「一次修复收敛」是假收敛

这是本次审阅最重要的结论，属于流程问题而非文本问题。

### 3.1 Reviewer 的判定前提是错的

Reviewer v1 报的唯一 issue：

| 字段 | 内容 |
| --- | --- |
| obligationId | `ch1-req-01` |
| severity | high |
| type | required_event / missing_element |
| evidence | 「他蹲下去，扒开雪。」 |
| suggestion | 「将发现玉佩的地点明确为雪落镇废井旁（如井台边、井口石板旁），**确保废井地点要素在正文中出现**」 |

而**初稿的第一行就是**：「雪落镇封山第七天，林动在**废井**边捡到一块暖玉。」
全篇「废井」出现 4 次（开篇、后巷听见井里风声、井口描述、逃亡时路过）。
Reviewer 断言一个**始终存在**的要素缺失。

同时 `ch1-req-01` 本身要求的「遇雪不冷、贴近炉火浮出微光纹路」，初稿两样都有：
「雪落在玉面上，不积，化成细小的水珠」「他把玉佩摸出来，凑到炉口。火光一映，玉面上
浮出东西……星点重新亮起」。**这条义务在初稿里本来就是满足的。**

### 3.2 所以「修复」什么都没修

初稿 → 候选的全部差异是 3 行（用 `diff` 核过）：首句加「镇西」「井台旁」、
井口描述加「井台上积着厚雪」「在井台边」、动作句「他蹲下去」→「他蹲在井口石板旁」。
全是措辞层面的补充，没有一处改变事件、顺序或参与者。

**修复能力在本轮没有得到任何验证。** 它只是在为一个不存在的缺口补字，然后复验自然通过。

### 3.3 确定性的证据校验挡不住这一类错误

现有防线要求「evidence 必须逐字来自当前候选」——「他蹲下去，扒开雪。」确实逐字存在，
也确实位于拾玉段落。**证据可定位 ≠ 断言为真。** 我们的确定性检查只能证明引用没造假，
不能证明「这个要素确实缺失」这个判断本身成立。

这类错误的表现是：**suggestion 读起来合理，但 premise 是假的**，而 evidence 又恰好
可定位，于是所有自动化门禁都会放行。

### 3.4 建议

1. **在义务链路上补一条「缺席断言需可证伪」的检查**：Reviewer 报 `missing_element` 类
   问题时，必须给出「已在这些位置查找过」的依据，或者由确定性代码检查该要素是否真的
   不在正文/上下文中；出现即反证。
2. **把 `missing_element` 与 `contradiction` 分开处理**：前者依赖「没找到」的判断，比
   「找到了矛盾」脆弱得多，应要求更强的证据或降低默认 severity。
3. **本轮 M1 的「一次修复收敛」在验收文档中不得作为 Repair 能力的证据**，已在
   [BETA-A2-M1-RESULT.md](./BETA-A2-M1-RESULT.md) 的观察项里记录；这里给出更明确的
   结论：**Repair 收敛能力仍未得到验证**（失败路径探针用的是人工构造的违规稿，验证的
   是「识别 + 修复能收敛」，不是「真实候选上的误判修复」）。
