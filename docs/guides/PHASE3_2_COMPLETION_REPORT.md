## 💡 关键决策记录

### 为什么不改动 ChapterEditorShell？

**原因**：
1. 该组件的生成逻辑非常复杂（多个 mutation）
2. 现有逻辑是云端 API 的紧耦合
3. 改动它需要理解整个编辑流程才能避免破坏
4. 风险收益比不划算

**替代方案**：
- 在 API 层添加路由逻辑（已完成）
- 后续在编辑流程中集成时，调用 API 层的 `shouldUseLocalGeneration()` 进行判断
- 这样既避免了过度改动，又保留了灵活性

### 为什么选择在标题栏放模式选择器？

**原因**：
1. 用户每次编辑都会看到，增加可见性
2. 与其他工作台操作（简易模式、自动导演）并列，逻辑统一
3. 标题栏有足够空间
4. 用户切换模式通常是有意的长期选择，不是频繁操作
